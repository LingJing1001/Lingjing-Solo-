## 15:4x tu93 世界模型完全破解（帧感知路线可建）

- **滚动/旋转之谜 → 否**：墙图互相关在稳定帧间残差 **0.000**，迷宫是**静止的**。唯一异常是**关卡入口那一帧是过渡动画帧**（best offset 漂到 (0,2)/(2,2)）。

## 17:17 闭卷 tu93 从 L3 推到 L6（3 个真 bug + 1 条反应式规则）

承接 16:5x 的 Step2B（L0–L3，闭卷 headline 1.1756）。本轮把 tu93 闭卷能力推到 **L0–L6（7 关）**，
**零罐头、零引擎读、零 per-level 硬编码**。三个根因全部定位到具体行：

1. **L4 卡死 = `_reconcile` 用位置列表 zip 比巡逻物**（`tu93_solver.py`）。
   两个巡逻块落到同一节点时帧里只剩 3 格（4 块塌成 3），`zip` 逐元素比 → 找不到相位 → `_broken=True` 永久 hold。
   离线 `plan_path` 对 L4 明明有效（29 步盲执行通关），说明是读数逻辑不是模型。
   **修**：比较**节点集合**而非位置列表；再进一步改成**子集**匹配（`seen_set <= {p.at(j)}`），
   因为 L5 的巡逻块会**钻到色 8 危险物下面被遮住**，观测量是预测集的真子集。
   证据脚本：`state/_dbg_l4reconcile.py`（zip-cands=[] 而 set-cands 恒含真相位）。

2. **L5 送死 = `_hazard_owner` 单值覆盖**（`tu93_frame.py`）。这是本轮最硬的一个。
   危险物的**视线格**可以同时被多个危险物盯上：L5 的 `(14,8)` 同时被 `(14,10)`（朝 W）和 `(16,8)`（朝 N）盯。
   旧实现 `owner[cell] = (er,ec)` 是「后写覆盖」，`(16,8)` 把 `(14,10)` 冲掉；
   而当 `(16,8)` 已被清、`(14,10)` 还活着时，模型误判 `(14,8)` 安全 → 走进视线 → GAME_OVER。
   **修**：`owner[cell] = {所有盯它的危险物}`，`_steps` 要求 `watchers <= cleared`（全部清完才放行）。
   同时删掉上一轮为绕这个 bug 加的 `MAX_HAZARD_STEPS=2` 保守闸门（它把 L5 的合法 30 步解误拒）。
   证据脚本：`state/_dbg_l5diff.py`（同一 k=21、同一 A1，参考解活 / 我死；节点级 diff 直指 (10,8)/(14,10)/(16,8)）。

3. **L6 = 巡逻物会拐弯**（不是直线反弹）。L3–L5 的巡逻物在直走廊上 bounce，可用 `k -> node` 建模；
   L6 的巡逻物沿整个迷宫走廊**绕圈拐弯**，且拐弯规则不自洽（"prefer straight" 在 `(12,12)` 被反例推翻）。
   所以**不存在 `k -> node` 函数**，时空规划不可用。
   **修**：加**反应式规则**（`patrol_next_cells` + solver 的 reactive 分支）。
   依据一条可证的生存律：巡逻块**每有效移动推进 1 节点**且**把下一步朝向画在帧里**（3×3 里那枚异色像素的偏移），
   所以只要**永不落在它「即将进入」的格**就安全（落在它**当前**格是交换，它已经走了）。
   模型失配（`_broken`）时切到这条路：避开 next cell 的 BFS，被堵就侧移/回退。

**验收**：`state/_verify_tu93_solver.py 3000` →
`L0→1@18, 1→2@29, 2→3@55, 3→4@73, 4→5@103, 5→6@134, 6→7@151`，`RESULT levels=7 state=NOT_FINISHED steps=3000 resyncs=0`。
**L0–L3 步数零回退**（18/29/55/73 不变）。3000 拍零死亡。

**未解决边界（诚实记录）**：
- **L7**：巡逻块在 `(6,12)` **连续 7 个有效移动不动**，之后才开始绕全图（`state/_dbg_l7*`）。
  它**不是**有效移动数的函数（A5 与有效移动交替测试过）。所以 L7 主动 hold（安全，不送死）。
- **L8** 未触达（L7 卡住）。
- 新增测试 11 个（`tests/test_tu93_frame.py`：视线多盯者、巡逻 bounce/走廊提取/next_cells、
  `plan_path` 不撞巡逻物 / 被封锁返回 None、`_reconcile` 重叠+遮挡容错 / 失配 stand down、反应式不踩 next cell）。

## icm_agent.py 深度接入读图栈（17:40 完成改写）

用户选择「方案 3」：ICM 退化为挂在 `PerceptionEncoder.perceive()` 之上的探索头，读图全部共用项目栈。

### 改写后的数据流（与主链同一条读图路径）
```
extract_grid/state/levels/available_actions  -> Frame
PerceptionEncoder.perceive(prev, cur, ...)   -> PerceptionSnapshot
LevelStability.observe(grid)                 -> raw/board/hud delta, board_changed
rerank_click_candidates(objects, shape, ...) -> 点击候选（chrome 降权 + 内部点）
normalize_observation(...)                    -> NormalizedObservation（R4，存在 perc.observation）
```
观察向量 = 128 维 L2 归一化感知特征 ⊕ 13 个标量摘要 = **141 维**（`PerceptionStack.obs_dim`）。
ICM 的 φ / forward / inverse 与策略都建在这 141 维上，网络是 MLP（不再自己从像素学卷积）。

### 三个实质变化
1. **内在奖励用 `board_changed` 门控**：`settled and not board_changed` 的转移拿 0（HUD-only 变化不再算新奇）。
2. **ACTION6 坐标不再用 4096 维头**：候选来自 `rerank_click_candidates`（最多 8 个）+ 末位「全域随机」槽 = 9 类分布。
3. **状态/关卡/合法动作全走 core 提取器**；动作历史以 `ActionRecord` 写进 R4 契约。

### 踩到并修掉的坑
- **模块级 `@dataclass` 会崩**：`benchmark_all_games._load_agent` 用 `spec_from_file_location` 但**不注册进 `sys.modules`**，dataclass 装饰器访问 `sys.modules[cls.__module__]` 时 AttributeError。→ 模板内 `ReadOut` 改为普通类 + `__slots__`。**任何后续模板都不要在模块级用 dataclass**（除非 harness 补 `sys.modules[spec.name] = mod`）。
- `FrameData.frame` 是**层的列表**（`[grid2d]`），不是 `[[grid2d]]`；`extract_grid` 取 `layers[-1]`。
- `FrameData.available_actions` 是 **int 列表**（1..7），`extract_available_actions` 内部走 `from_available_ids` 转规范名。
- `ComplexAction` 的 `x,y` 限定 `ge=0 le=63` → 64×64 坐标域确认。
- 基类 `Agent.action_counter` 也会自增，模板改用独立的 `step_count` 避免双重计数。
- `set_data` 传 `{"game_id":..., "x":col, "y":row}`（列=x、行=y）；官方 Playback 也带 game_id。
