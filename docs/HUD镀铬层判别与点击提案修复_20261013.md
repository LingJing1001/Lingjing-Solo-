## 1. 为什么先做时序、却被证伪

`ceax_controller.py` 用 `delta_pixels <= 2`（:689 / :739 / :754 / :848 / :875）判断"动作无效果"，
用 `effect = min(1.0, delta_pixels / 64.0)`（:673）给动作记功。而 `my_agent.py` 喂进去的是
**全屏像素差**。若 HUD 每步自跳，这些阈值永不触发、记功被系统性抬高——这是 B 最初的全部理由。

实测否掉了它。两轮独立验证：

| 量 | 值 |
|---|---|
| 池化步数（23 局，关卡内） | 2232 |
| `raw_delta > 0` 的步数 | 2025（90.7%） |
| **`raw_delta > 0` 但 `board_delta == 0`** | **0（0.0%）** |
| 单像素最高变化频率（`layers[-1]`，即 `delta_px` 读的那层） | **0.750** |
| 单像素最高变化频率（任意层） | 0.833 |
| `freq > 0.5` 的像素数（`layers[-1]`） | 63（cd82）+ 5（re86）+ 32（vc33）= 100 |

即**这批游戏里的 HUD 是"画上去就不动"的**，不是动画的。原因也说得通：这些 episode 是
**本 agent 自己**跑出来的轨迹，而它从未在某一关待得足够久以触发计时类 HUD。

> 附带纠正一个我自己写错的地方：`extract_grid`（`lingjing_solo/core/utils.py:76,84`）返回
> `layers[-1]`——**最后一层**，不是第 0 层。而 `my_agent.py:2134` 的注释正写着 lf52 的
> "HUD 计数器"在最后一层。我第一版探针只测了第 0 层，测错了层；改成最后一层后结论不变。

## 2. 强阳性：点击提案的头号候选是镀铬层

### 2.1 旧规则实际在做什么

`_perc_click_candidates`（`my_agent.py:375`）原逻辑：用 `PerceptionEncoder.segment` 分割
→ **按像素数降序** → 逐个取 **bbox 中心** → 前 8 个当候选。

两个独立缺陷：

1. **镀铬层排第一。** `PerceptionEncoder.segment` 按"颜色相同且 4-连通"合并，于是整屏背景
   （某一纯色）就是一个 2000~3900 像素的巨块，稳稳排第一。
2. **bbox 中心可能不在物体上。** 环/框/L 形的 bbox 中心落在空洞里，点下去点的是别的东西。

### 2.2 实测（23 局真帧，`state/_probe_hud2_out.txt`）

| 指标 | 旧规则 | 新规则 |
|---|---|---|
| 头号候选是镀铬层 | **19/23（83%）** | **0/23（0%）** |
| 头号候选的取点在物体**外** | **10/23（43%）** | **0/23** |
| 取点落在真实物体格上 | 13/23 | **23/23（100%）** |

最直接的证据是那 8 局：**旧规则的头号候选点就是 `(31,31)` = 64×64 屏幕正中**
（cn04×3 的 3704px 整屏纯色、ft09 2632px、ls20 2129px、re86 3862px、s5i5 3267px 的 bbox
中心）。也就是说**搜索的第一枪打向屏幕中心**。

### 2.3 端到端验证（跑真实 `my_agent.py`，不是复刻）

`state/_probe_perc_e2e.py` 直接 import 发布版 `my_agent.py` 调
`_perc_click_candidates(grid, prev=None, k=8)`，用 `PERC_AGENT_PATH=备份` 跑改造前，
再跑改造后对比（`state/_perc_click_before.json` / `_after.json`）：

```
first pick changed in 21/23 episodes
chrome points inside the returned top-8 : 53 -> 6   (out of 184 slots)
```

即 **top-8 候选槽里的镀铬点从 53/184（28.8%）降到 6/184（3.3%）**。
残留的 6 个全在 cn04（3 局 × 2）：cn04 有 8 个对象、其中 3 个判为镀铬层，
把镀铬层排到末尾后它们仍落在 8 个槽内。

这一步同时验证了**坐标顺序**（`rerank_click_candidates` 给 `(row, col)`，
`_add` 要 `(x, y)`，中间必须转置）——只复刻不 import 是测不出这类错的。

## 3. 判据：为什么是"变化频率"，以及为什么它这次没派上用场

`stability.py` 的核心是一个在线、因果、无模型的判别：

```
freq[r, c] = 本关内像素 (r,c) 发生变化的步数 / 步数
animated_mask = freq >= ANIM_RATIO (0.9)     # 仅在有足够历史后生效
board_changed = ((prev != cur) & ~animated_mask).any()
```

自跳的像素与 agent 的选择无关 → 它是镀铬层；只在部分步变化的像素是被动作驱动的 → 玩法区。
冷启动没有历史时，用几何补位：贴边 ≥1 边、长宽比 ≥4 的细条、占满整行/列的带、占屏 ≥40% 的
巨块。两者加权成一个 `[0,1]` 分数，`>= 0.5` 判为镀铬层。

**镀铬层只是降级排序，不丢弃**——从未见过的游戏上，边框有可能真是要点的目标。

### 3.1 实现里被抓到的两个真错（都是单测先红）

1. **`animated_mask` 的 off-by-one。** 原写法在累加本步 diff *之前*算掩码，分母是步数、
   分子少一次 → 一个真正每步都变的像素只算到 `10/12 = 0.833`，够不到 0.9。
   改为分母用 `_diffs`（观察到的差分次数，不含无前驱的第一帧），并把本步 diff 先折进去。
2. **完全自走的物体只得 0.45**，差一点够不到 0.5。改为"物体 ≥50% 的格子在自走"这一条
   单独贡献 **0.50** —— 一个整体自走的物体本身就是镀铬层，不该靠几何补分。

因为没有真实的自走 HUD 可用，这两条**只能靠合成用例暴露**：`tests/test_perception_stability.py`
构造一个每步翻转的格子，断言 `raw_delta == 1` 而 `board_changed is False`。18 例全过。

## 5. 未接线的部分（有意）

`LevelStability` 已实现、已单测，但**不接进主链**，因为实测收益为零（§1）。
若将来发现真的自走 HUD，接线配方：

```python
# __init__ 附近
self._hud = LevelStability((64, 64), warmup=6)

# 换关 / RESET 时
self._hud.reset()

# 每步拿到 grid 之后（extract_grid(latest_frame) 之后即可）
self._hud.observe(grid)

# 需要"动作是否真的改变了玩法区"时，替代全屏 delta
info = self._hud.observe(grid)
if not info["board_changed"]:
    ...   # 这一步没有任何受控对象移动
```

以及把 `self._hud` 传给 `rerank_click_candidates(..., animated=..., changed=..., settled=...)`
以启用时序证据（当前只用了几何）。

## 8. 风险与未验证

1. **收益未在分数上验证。** 本次只证明"提案的候选质量变好"，**没有跑过 benchmark**，所以
   **canned / closed-book 分数是否变化未知**。按论文口径这两者都不官方计分，但封闭集上
   点击类游戏（cn04 / s5i5 / ft09 等）的搜索起点确实变了，值得用一次本地跑测确认不退化。
2. ~~`rerank_click_candidates` 是新增代码路径~~ **已关闭**：强制 import 失败后回退结果与
   改造前逐局一致（§6）。剩余风险只是"新路径本身在真实游戏里是否总是优于旧路径"——
   本地真帧上是（§2.2/2.3），但没跑过 benchmark。
3. **时序半边未接线**，若隐藏计分集里有动画 HUD，当前代码不会处理它——见 §5 的接线配方。
4. `_build_search_click_acts`（`my_agent.py:462`）里的 `_perc_click_candidates` 调用点
   **仍然传 `prev=None`**，即搜索动作展开那一处拿不到时序证据；同时它还有一条热图路径
   （`arc_adaptor/click_heatmap`）排在 perc 之前，**那条路径没有做镀铬层过滤**。这是下一个
   可以查的点。
