## 二、多智能体差距分析



| 能力        | 当前状态                                     | 差距                      |
| --------- | ---------------------------------------- | ----------------------- |
| **角色分化**  | 所有 Agent 同质（都是 EvacuationAgent）          | 没有侦察 / 执行 / 指挥等角色分化     |
| **显式通信**  | 只有通过场的隐式交互（邻居排斥）                         | 没有 Agent 间消息通道          |
| **协作任务**  | 场景都是 "单 Agent 独立可达目标"                    | 没有需要 2+ Agent 协作才能完成的任务 |
| **层级组织**  | 扁平，所有 Agent 平等                           | 没有 Leader/Follower 或子团队 |
| **长期记忆**  | Agent 只有单 tick 感知                        | 没有跨 tick 的状态 / 记忆       |
| **C 值闭环** | ReflectionSignal.c\_value 定义了但未接入 Engine | 没有自指监视接入主循环             |

## 三、迭代路线

### V16.0 — 角色分化 + 通信通道

**目标**：从同质 Agent 升级为异构角色，加一条显式 Agent 间通信通道。

**改动**：



1. `core/message.py`**（新建）**：Agent 间消息通道



```
@dataclass
class AgentMessage:
    sender_id: int
    receiver_id: int  # -1 = 广播
    msg_type: str    # "info" | "command" | "request"
    payload: dict
    tick: int
```



1. **Agent 基类加&#x20;**`inbox: List[AgentMessage]`：每 tick Engine 投递消息

2. **新建&#x20;**`ReconAgent`**（侦察角色）**：速度快、感知范围大、不写场

3. **新建&#x20;**`WorkerAgent`**（执行角色）**：速度慢、写场强、听指挥

**验收测试**：



* C23：ReconAgent 发消息，WorkerAgent 收到（inbox 非空）

* C24：广播消息（receiver\_id=-1）所有 Agent 都收到

* C25：不同角色在同一场上共存，互不干扰



***

### V16.1 — 协作场景（搬箱子）

**目标**：写一个需要 2+ Agent 协作才能完成的场景，验证协作能力。

**改动**：



1. `scenarios/carrybox.py`**（新建）**：

* 一个箱子（重物），单个 Agent 推不动（阻力 > 推力）

* 2 个 Agent 同时推 → 合力 > 阻力 → 箱子移动

* 箱子到达目标点 → 成功

1. **Box 对象**：带质量、位置、受力累积

2. **Agent 写场**：推箱子时在箱子位置施加力源项

**验收测试**：



* E9：单 Agent 推箱子不动（合力 < 阻力）

* E10：双 Agent 同时推 → 箱子移动到目标

* E11：协作过程守恒（ΔΣφ = dt・ΣJ 仍成立）



***

### V16.2 — 层级组织（Leader/Follower）

**目标**：Leader 分配任务，Follower 执行，验证层级结构。

**改动**：



1. **LeaderAgent**：读场 + 分配子目标给 Follower（发 command 消息）

2. **FollowerAgent**：读 Leader 的 command，调整自己的决策方向

3. **场景**：多目标点，Leader 分配 Follower 去不同目标

**验收测试**：



* C26：Leader 发 command，Follower 朝 command 指定的方向移动

* C27：多个 Follower 被分配到不同目标（分工，不挤一起）

* C28：Leader 离线后 Follower 回退到默认行为



***

### V16.3 — C 值闭环 + 长期记忆

**目标**：把 ReflectionSignal.c\_value 接入 Engine 主循环，Agent 有跨 tick 记忆。

**改动**：



1. **Engine.step 加 C 值计算**：每 tick 结束时算 `c_value = f(field.phi, agents)`

2. **Agent 加 memory: dict**：跨 tick 记忆（访问过的位置、成功 / 失败统计）

3. **C 值阈值触发**：c\_value 超过阈值 → Agent 调整策略（探索 / 反射）

**验收测试**：



* C29：Engine.consensus.records 里 c\_value 每 tick 都有值

* C30：Agent memory 在 N tick 后非空（有记忆）

* C31：c\_value 高时 Agent 行为变化（策略调整）

## 五、诚实边界



1. **不引入 LLM / 大模型**：当前 Agent 决策是规则驱动（梯度 + 排斥），多智能体迭代先把结构搭好，智能层后续再接。

2. **通信通道是黑板模型**：消息存在 Engine 维护的全局黑板上，不是点对点网络。简单但够用。

3. **协作场景是物理协作**：搬箱子是力的协作，不是语义协作。语义协作（分工讨论）留待 LLM 接入后。

4. **8 个 torch 测试仍未跑**：AOP 神经网络相关，不在多智能体迭代范围。
