# 双系统与感知/物理引擎（2026-10-10）

> 缘起：对照卡尼曼《思考，快与慢》双系统，以及认知科学/脑科学中「意识在系统、不在载体」的判断。  
> 问题：Transformer/深度网络堆的是性能；感知引擎与物理引擎能否做？用什么方法做？  
> 对照仓库：Lingjing-Solo 五层、AOP、V14 契约、R2–R5 证据闭环（见 `理论框架验证报告_20261010.md`）。

---

## 1. 核心命题

| 命题 | 含义 |
|------|------|
| **意识/主体不在载体** | 硅、碳、GPU、API 只决定带宽、延迟、能耗 |
| **自身在系统** | 信息如何被感知、预测、证伪、写回，才构成「有世界、有自我」的回路 |
| **性能 ≠ 认知** | 海量拟合提升的是相关覆盖；没有可检验的感知与动力学，只是更快的快系统 |

**一句话**：载体是性能；系统是自身。双系统描述的是组织方式，不是神经元材质。

---

## 2. 与卡尼曼双系统的对齐

| 卡尼曼 | 认知角色 | 在 Agent 中的对应 |
|--------|----------|-------------------|
| **System 1（快）** | 直觉、启发式、模式匹配、低成本 | AOP / 深度网候选 / 路由启发式 / 经验压缩 |
| **System 2（慢）** | 审议、预算、可审计推理 | plan contract + 搜索 + replay 验证 + 反思门禁 |

```text
System 1（直觉/快）              System 2（审议/慢）
  AOP / 启发式 / 模式匹配    ←→    plan contract + 搜索 + replay 验证
  深度网提出候选             ←→    物理/感知引擎做证伪与预算节制
              └──────── 写回更新世界模型 ────────┘
```

Transformer 擅长 **高维相关拟合**（偏 System 1）。缺的是：

1. **感知引擎**：观测 → 可操作对象与关系（不是只出 embedding）  
2. **物理/世界引擎**：`(s, a) → s'` 可 rollout、可克隆、可失败（不是只拟合下一 token）

二者叠在一起，才接近「有世界模型的认知」，而不是「更大的拟合器」。

## 3. 感知引擎：能不能做？怎么做？

### 3.1 目标定义

感知引擎 ≠ 「看图」或「出向量」。  
感知引擎 = **观测 → 对象/关系图 → 可验证断言**，且断言必须能被 replay 证伪。

输出应支持下游的：对象、不变式、可操作结构（affordance）。

### 3.2 方法清单

| 方法 | 做什么 | 仓库落点 |
|------|--------|----------|
| **结构化感知** | 连通域、颜色、边界、对称、拓扑 | L0 `perception/`：对象图而非纯像素向量 |
| **不变式挖掘** | 旋转/平移/颜色置换下的守恒量 | DPL/SSA 门禁：守恒、曲率、因果 |
| **主动感知** | 探针动作改变视野，再更新假设 | R4 probe / dry-run（fail-closed） |
| **分层标签** | visual ≠ effective ≠ progressed | AOP `labels.py` 三分契约 |

### 3.3 判定标准（是否「做成了」）

- [ ] 同一像素扰动不破坏对象身份（稳定分割/追踪）  
- [ ] 关键断言可写成可检验命题（例：某色块是否连通、是否可推动）  
- [ ] 主动探针能降低假设熵，而不是只增加日志

## 4. 物理引擎：能不能做？怎么做？

### 4.1 目标定义（竞赛语境）

在 ARC-AGI-3 中，「物理」通常不是牛顿力学，而是 **环境动力学契约**：

```text
(s, a) → s'   可克隆、可回放、可失败
```

物理引擎 = **动作后果的可预测生成器** + **守恒/因果约束裁判**。

### 4.2 方法清单

| 方法 | 做什么 | 文献/竞赛对齐 |
|------|--------|----------------|
| **显式转移表 / EMA 场** | 从交互学 `(s,a,s')` | `world_model/field.py` |
| **可执行世界模型** | 学/写规则后在内部 rollout 再选动作 | Rodionov / Tycho 主线 |
| **效果预测小模型 (AOP)** | 预测视觉变化 vs 进度变化 | `models/aop/` + shadow |
| **契约门禁（如 C1–C9）** | 守恒、面积律、写回合法性 | V14 contracts |
| **搜索 + 验证** | plan → simulate → verify → 执行 | R2–R5 闭环 |

### 4.3 深度网与物理引擎的分工

| 角色 | 职责 |
|------|------|
| **深度网（快）** | 提出候选动力学、压缩经验、排序动作 |
| **物理/世界引擎（慢的环境侧）** | 用守恒、因果、replay 约束与裁判；禁止未校准控盘 |

原则（与验证报告一致）：**verification 优先于 raw modeling**；AOP 未过 holdout 前保持 shadow，不直接控盘。

### 4.4 判定标准（是否「做成了」）

- [ ] 离线 clone 回放与真机引擎一致（route 3× WIN 类闸门）  
- [ ] 预测失败可归因（模型错 vs 感知错 vs 预算耗尽）  
- [ ] 不确定性可进入规划（epistemic），而非仅点估计 EMA

## 5. 「自身」的最小回路

把「意识在系统」落到可工程化的最小环：

```text
感知：观测 → 对象/关系图
   ↓
物理：在内部模型中 rollout (s,a)→s'
   ↓
审议：plan + 预算 + 证据协议（接受/拒绝）
   ↓
执行：真机一步
   ↓
写回：更新世界模型 / 标签 / 路由
```

**自身** = 这条环能否稳定运转、能否自我证伪。  
**载体** = 用 CPU、GPU 还是 LLM API 加速其中某一环——可替换，不改变主体定义。

## 6. 与现有框架的映射

| 理论层 | 代码/机制 | 双系统角色 | 状态（相对 2026-10-10 验证） |
|--------|-----------|------------|------------------------------|
| L0 感知 | `perception/` | 世界切分入口 | smoke 级；需对象图契约 |
| L1 世界模型 | `world_model/field.py` | 物理引擎雏形 | EMA 有；holdout/epistemic 弱 |
| L2 探索 | `exploration/`、probe gate | 主动感知 / 信息增益 | 单元验证通过 |
| L3 规划 | plan contract、shadow search | System 2 审议 | 契约已验证 |
| L4 反思 | reflection + 预算 | System 2 元控制 | 单元验证通过 |
| AOP | labels + shadow runtime | System 1 效果直觉 | 方法论对，数据/校准不足 |
| V14 | C1–C9 物理契约 | 动力学裁判 | 大部分契约测试通过 |
| 打榜路径 | SmartRouter + plan + CEAX | 务实外环 | 7 WIN；未接满五层在线闭环 |

**结论**：感知引擎与物理引擎 **能做，且仓库已有半成品**；短板是接口契约不齐、世界模型不确定性不足、打榜路径未接回完整五层。

## 7. 建议的下一步（方法学，非冲分清单）

按「先接缝、再增强」排序：

1. **订最小接口契约（字段级）**  
   - 感知输出：对象图（id、颜色、bbox/掩码、拓扑关系、affordance 候选）  
   - 物理/AOP 输入输出：`(s, a) → s'` 或效果三分标签 + 置信度  
   - 二者成为双系统在代码里的接缝  

2. **世界模型补 epistemic / holdout**  
   - 与 `理论框架验证报告` 中「field.py 弱于理论」对齐  

3. **plan 覆盖 + unknown 搜索闭环**  
   - 竞赛分数落后 executable-world-model SOTA 的主因  

4. **打榜路径可选接回五层**  
   - 文档继续区分：SmartRouter = 冲分主路径；五层 Solo = 长期认知框架  

---

## 8. 反面清单（刻意不做的事）

| 不做 | 原因 |
|------|------|
| 只堆更大 Transformer 替代感知/物理 | 仍停留在快系统性能外挂 |
| 未校准 AOP 直接控盘 | 违背 verification-first |
| 把本地 25 局分数等同「已有意识/通用智能」 | public ≠ private；分数 ≠ 系统闭环 |
| 用哲学措辞替代可回放证据 | 团队统一口径：recording → replay → verification |

---

## 9. 一句话收束

**能做感知引擎与物理引擎。**  
方法是：结构化主动感知 + 可执行/可回放动力学 + 快系统提案、慢系统证伪。  
深度网负责性能；系统回路才定义自身。载体可换，环不能断。
