# Duck 分割器移植 + 真帧验证

日期：2026-10-13
状态：已完成移植与三轮实测（选项 A）
产物：`lingjing_solo/perception/segmentation.py`（新）
验证脚本：`state/_verify_segmentation{,2,3}.py`、输出 `state/_verify_segmentation*_out.txt`

---

## 一、为什么做这件事

上一轮读完 Duck harness 源码后，有两条待验证的判断：

1. Duck 的物体表示和我们的**方向一致**（都不用原始网格）但**产物天差地别**——它是带
   `hash` / `children` / `boundary` / 邻接表的对象图，我们是 16 个标量。
2. Duck 的 prompt 里明确警告过一个失败模式："把分割出来的边缘条误认成可点击的拼图块"——
   而这正是 `my_agent.py:_perc_click_candidates` 在做的事。

A 方案就是：把那段 stdlib-only 的分割器移植进来，**先在真帧上验证它到底能不能对上物体**，
再决定要不要接进点击提案。验证不需要模型、不需要 GPU。

---

## 二、移植了什么

`lingjing_solo/perception/segmentation.py`，源自 `Tufalabs/duck-harness`（MIT）
`ARC3-Inference/inference/utils/segmentation.py`，**标准库 only**（与上游同约束，
便于日后原样嵌进 Python-tool sandbox）。

能力对照——斜体是本次新增：

| 能力 | `PerceptionEncoder.segment`（原有） | 移植后 |
|---|---|---|
| 连通域 | union-find，4-连通 | flood fill，4-连通 |
| 颜色 0 | **当背景跳过** | 参与分割（是普通颜色） |
| 物体键 | 无 | *平移不变 hash* |
| 嵌套 | 无 | *children 树（谁是容器谁是内容）* |
| 形状 | 仅 bbox | *Moore 轮廓 → 角点序列* |
| 关系 | 无 | *组件邻接表* |

**一处性能改造**：上游 containment 是 O(n·H·W) 的逐组件 flood fill，实测 **87.9 ms/帧**，
对 agent 每步调用不可接受。改成在组件邻接图上 BFS（"a 被 b 包围 ⟺ 删掉 b 后 a 与边界
不连通"，精确等价），**20.4 ms/帧，快 4.3×**。上游实现保留为
`_compute_enclosers_floodfill(containment="floodfill")`，抽样 **134 帧 / 23 局，
0 处不一致**。

## 三、验证：三个问题，2427 帧

语料：`data/aop/episodes` 全部 23 条 `recording.jsonl`，2427 帧，**107,835 个对象实例**。

### 3.1 先纠正一个会被误读的数字

第一轮按 **unique hash 计数**统计，ar25 显示"1457 个 hash 里 1051 个只出现 1 帧"，
看着像 hash 完全不可用。**按实例加权后结论反转**：

> 池化后，**71.2% 的对象实例**属于"在 ≥80% 帧中出现的 hash"；只有 16.6% 属于 <20% 的。
> 也就是那 1051 个一次性 hash 只占实例的 5%。

**结论：unique 计数被碎片污染，实例加权才是可读口径。**

### 3.2 关卡切换是个陷阱

按整局统计 vs 按关卡内统计，差得很远：

| episode | 整局 | 关卡内 |
|---|---|---|
| vc33_success | 29.3% | **72.1%** |
| ft09_fail | 84.5% | **95.8%** |
| sb26_fail | 72.5% | **88.5%** |
| cn04_fail | 34.1% | **34.7%**（唯一没改善的） |

关卡切换会重画全屏，被误算成"hash 抖动"。**正确口径必须是关卡内。**
cn04 是唯一真抖动的局。

### 3.3 核心发现：精确形状 hash 在大物体上崩溃

按物体像素数分层（关卡内，23 局池化）：

| 像素 | hash | 颜色+像素数 | 颜色+面积桶 | 仅颜色 |
|---|---|---|---|---|
| 1 | 99.6% | 99.6% | 99.6% | 100.0% |
| 2-4 | 96.6% | 96.7% | 97.0% | 99.9% |
| 5-9 | 92.5% | 92.7% | 93.4% | 99.9% |
| 10-49 | 79.1% | 82.0% | 89.4% | 99.5% |
| **50-199** | **41.5%** | **48.6%** | **81.9%** | 100.0% |
| **200-999** | **15.2%** | **20.0%** | **77.8%** | 100.0% |
| 1000+ | 21.6% | 29.8% | 97.1% | 99.9% |

**为什么**：hash 是"颜色 + 精确归一化形状"。大物体多是容器/框/板，会被穿透、遮挡、
内部图案变化——连通域形状一变，hash 就变。而 `颜色+精确像素数`几乎一样糟（48.6%），
说明**不是面积在变，是形状在变**；`颜色+面积对数桶`却能到 81.9%，说明面积漂移
幅度小于 2×。

**但要注意反向代价**——更稳的键区分度更低：

| 键 | 每局 distinct key 数 | 50-199px 持久率 |
|---|---|---|
| hash | 278 | 41.5% |
| 颜色+像素数 | 163 | 48.6% |
| **颜色+面积桶** | **31** | **81.9%** |
| 仅颜色 | 9 | 100%（**等于没用**） |

`仅颜色` 99.8% 的"稳定"是平凡的：每局只有 9 个键，"所有红色物体都是同一个"。

### 3.4 歧义：hash 不能唯一识别物体

**100% 的帧**都存在"同一 hash 出现多次"。ar25 最极端——某一帧同一个 hash 有
**60 个实例**。所以"用 hash 定位物体"这个用法不成立，**必须 hash + 位置做最近邻配对**。

### 3.5 可追踪的移动物体确实存在

E 段筛"关卡内持久 + 位置变化 >2 次 + 尺寸适中"的物体：

| episode | 可追踪移动物体数 | 例 |
|---|---|---|
| sb26_fail | 24 | `9e112462d9ef94ed` px=4, 63 个位置 |
| ft09_fail | 16 | 同上 |
| vc33_success | 9 | `f5684b44a28330d7` px=16, 39 个位置 |
| s5i5_fail | 8 | px=3 |
| ls20_success | 7 | px=10, 67 个位置 |
| ar25_success | 6 | px=9, **104 个位置** |

这些是**小而刚性**的物体——正好是 hash 擅长的那一档。

## 四、结论

**A 方案可行，但不是银弹。** 诚实的评价：

- ✅ **移植成功**：性能 20.4 ms/帧（原版 87.9），逐位等价，stdlib-only，无新依赖。
- ✅ **净增能力**：`children` 嵌套树和 `boundary` 轮廓角点是 perception 此前完全没有的，
  它们与 hash 无关，不受 3.3 的退化影响。
- ⚠️ **hash 只在"小而刚性的物体"（<10px，92-99%）上有效**；游戏里那些 50+px 的
  容器/板/框，hash 只有 15-42%。
- ❌ **不能单独用 hash 定位物体**（100% 帧有多实例，最多 60 个）。
- 📌 **若要做跨帧追踪，键应该用 `(颜色, 面积对数桶)` + 位置最近邻**，而不是纯 hash。

**这直接修正了上一轮文档里"移植 `_object_hash` 就能改善点击提案"的乐观预期**——
改善只发生在小物体上。

## 五、对 `my_agent.py` 的具体改进建议（未实施）

读 `_perc_click_candidates`（`my_agent.py:375-441`）后确认的问题：

1. **候选按 `pixels` 降序取 bbox 中心 → 最大组件（背景/边框）排第一。**
   原 segment 还把颜色 0 当背景跳过，若背景不是 0（ar25 用 9），背景会被当成
   "最大物体"，中心点直接进候选。**这就是 Duck prompt 警告的 HUD 污染。**
2. **bbox 中心可能落在物体外**（L 形/环形/凹形），应改用 `boundary` 的角点质心。
3. **没有嵌套信息**：无法区分"框"和"框里的东西"，两者都被当独立候选。

可用的替代（全部基于本次移植，纯逻辑）：

- 排除"覆盖面积最大的组件"（背景）与"紧贴边缘且细长"的组件（HUD 条）；
- 候选点改用 `boundary` 的形心；
- 用 `children` 优先选**叶子**（被包含者），或选"有 children 但不是背景"的容器；
- 跨帧只在 **`(颜色, 面积桶)` + 位置最近邻** 的键上做追踪。

> ⚠️ 硬约束（记忆里的事故记录）：**不能**用编辑工具直接改
> `integrations/ARC-AGI-3-Kaggle-Starter/agent/my_agent.py`，它会被重编码成
> UTF-16 + null byte 而损坏。本次未触碰该文件。
