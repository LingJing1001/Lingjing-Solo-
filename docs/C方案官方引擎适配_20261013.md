## 1. 官方契约（从源码实证，不是猜的）

`vendor/ARC-AGI-3-Agents/agents/agent.py`：

```python
class Agent(ABC):
    MAX_ACTIONS: int = 80
    def is_done(self, frames, latest_frame) -> bool: ...
    def choose_action(self, frames, latest_frame) -> GameAction: ...
    def main(self):                # 官方自己推进环境
        while not self.is_done(...) and self.action_counter <= self.MAX_ACTIONS:
            self.take_action(self.choose_action(frames, latest_frame))
```

构造签名（7 个位置参数，全都得给）：

```python
MyAgent(card_id, game_id, agent_name, ROOT_URL, record, arc_env, tags)
```

`Agent.state` 是 **property**（读 `frames[-1].state`），`Agent.frames` 是帧列表，
`MAX_ACTIONS` 生效条件是 `action_counter <= MAX_ACTIONS` ⇒ 设 20 实际跑 21 次。
引擎侧：`EnvironmentWrapper.reset() / .step(action, data, reasoning) -> FrameDataRaw`。

## 2. 两条接入路径，为什么必须都做

| | 离线自跑 | 官方提交 |
|:---|:---|:---|
| 谁推环境 | `Harness.run_episode` | `Agent.main()` 里的 `take_action` |
| 一次给几帧 | 一帧（我们控制） | 一帧（引擎回调） |
| 用途 | 本地评测、算 token、做 A/B | Kaggle 提交 |
| 入口 | `OfficialEnv` | `arc_env.HarnessAgent` |

两者**必须共用同一个 `EpisodeState`**（history / memory / 重置策略）。
否则本地验证过的提示词到了提交环境会因为 history 格式不一致而失效 ——
那正是"本地分不能预测云端"最容易复发的地方。

## 3. 动作映射与唯一的坐标换算点

| harness | 官方 | 说明 |
|:---|:---|:---|
| `UP` | `ACTION1` | MOVE_UP |
| `DOWN` | `ACTION2` | |
| `LEFT` | `ACTION3` | |
| `RIGHT` | `ACTION4` | |
| `SPACE` | `ACTION5` | 交互键 |
| `CLICK(row, col)` | `ACTION6` | **`set_data({"x": col, "y": row})`** |
| — | `ACTION7` / `RESET` | **刻意不暴露**（同 harness 不给 Undo 的理由） |

- **`(row, col) → (x, y)` 只在本模块换算一次**，别处一律用 harness 的 `Action`。
  实测：`CLICK(row=5, col=9)` → `{'x': 9, 'y': 5}`。
- **不可用时降级而不是作废**：引擎某一帧关掉了某个键（`available_actions`），
  就把动作换成第一个可用键（优先方向键 → SPACE → 点击），整步照样留下证据。
  实测：`CLICK` + `available=[1,2]` → `ACTION1`。
- `canonical_action_names()` 剔除 `RESET` 与噪声字符串（`"??"` 不会混进可用集）。

## 4. 帧 → 网格：四层剥离

真实结构是 `FrameDataRaw.frame = [np.ndarray(64,64)]` —— **列表套数组**（一帧一层）。
`frame_to_grid()` 逐层剥：`FrameData.frame` → `np.ndarray.tolist()` →
若是"帧列表"取最后一帧 → 得到 `list[list[int]]`。

兼容并实测通过：嵌套 list、裸 ndarray、帧列表、`FrameData` 对象、`FrameDataRaw`。
取不到一律返回 `None`（由上层记为一步失败），不抛异常。

## 5. `Harness.decide()`：把"出动作"从"跑一局"里拆出来

官方每次只回调一帧，所以原来的 `run_episode` 内部逻辑必须能被单独调用。新增：

```python
dec = harness.decide(frame, turn, history, memory)   # 纯观察→动作，不碰环境
# dec.graph / dec.code / dec.action / dec.result / dec.record / dec.prefix_tokens
```

`run_episode` 与 `HarnessAgent.choose_action` **都只调它**。
副产品：`EpisodeState` 独立成类，`position_signature()` / `shape_signature()`
从私有名提升为公开名（官方路径要用它判断"上一步动作改变了什么"）。

官方路径没有我们自己的 `env.step` 返回值可用，所以 `moved`/`changed` 改为比较
"上一次决策时的对象图"与"这一帧的对象图" —— 中间夹着的正是上一步动作，
即它的因果。

## 7. 接真帧立刻抓出的两个问题

### 7.1 ★ `FakeLLM` 有一个只在玩具网格上侥幸通过的 latent bug

FakeLLM 生成的代码末尾顶格写着 `memory['last'] = (a['r'], a['c'])`，
而 `a` 只在 `else:` 分支里定义。`FakeEnv` 的 8×8 网格**必定**同时含 color 5 和 3，
所以永远走 `else`，从来没暴露；接官方真帧（ar25 第 0 帧就没有 color 5）立刻：

```
NameError: name 'a' is not defined
```

已修（`memory['last']` 缩进进 `else`）。**这就是为什么必须接真帧**：
测试替身自己写错，测试替身永远测不出来。回归哨兵已加进 e2e 脚本（路径 1b）。

### 7.2 官方 `Agent.state` 是 property，不能占用这个名字

第一版把跨步状态存成 `self.state = EpisodeState(...)`，直接
`AttributeError: property 'state' has no setter`。改名 `self.ep_state`。
教训：**继承外部基类时，先扫一遍它的 property 再取属性名。**

## 8. 已知边界

1. **奖励信号是猜的**：官方逐步不给 reward，`OfficialEnv` 用
   "`levels_completed` 是否上升"当 reward=1.0、过关/终局当 `done`。
   这对单局统计够用，但不是官方计分（RHAE 是按基准步数算的）。
   要出分必须走官方 scorecard，不能拿 `EpisodeResult` 的 reward 当分数。
2. **`HarnessAgent` 没在 NORMAL/COMPETITION 模式验过**，只走了 OFFLINE。
   顺带发现：本机 `NORMAL` 模式**能联网**并拉到 25 个环境 ——
   所以"回归环境无网络"要靠**显式 `mode="offline"`**，不能靠它自己失败兜底。
3. **`available_actions` 的语义只按 id 解释**（0=RESET, 1..7=ACTION1..7），
   没验证所有游戏是否都遵守这个编码。
4. **没接真模型**：`RoundRobinLLM` / `FakeLLM` 都不看提示词，
   所以"提示词写得好不好"**依然没有被验证** —— 这是下一轮的第一件事。
5. `kernel-metadata.json` 仍是 `enable_gpu: false` 且无 `dataset_sources` /
   `model_sources`；C-Local 要提交必须改，但那是本地 serving 起量之后的事。
