## 0. 一句话结论

上一轮把 `harness/sandbox.py` 做到了"能跑、能拦"，但**跑完之后没有留下可比较的证据** ——
失败步只有一句错误字符串，没有 exit code、没有终止原因、没有状态差异。
这次按教程 Task2 的四层表把**证据字段补齐并钉进结构**，
使 `Harness` 每一步都产出一条可 JSON 化、可回放、可跨机比对的 `ExecutionRecord`。

**这是对我们最贵的一次教训（B 补丁"涨 3 局"实为并行会话改动的误归因）的直接工程化回应**：
先用 `RunJournal.diff_against()` 判定"两次运行的环境是否一致"，
不一致就拒绝把差异归因给策略。

## 1. 教程四层表 → 我们的实现

| 层 | 教程要求留的证据 | 我们的落点 |
|:---|:---|:---|
| 工具接口 | tool name、args、schema version | `ExecutionRecord.tool` / `.args` / `.schema_version`；`ToolSpec.signature()` 给出 `action(name:str, row:int\|None, col:int\|None) -> Action` |
| 执行隔离 | image、依赖锁定、资源配额 | `SandboxSpec.image` / `.deps_lock` / `.filesystem` / `.network` |
| 资源控制 | 预算、开始/结束时间、终止原因 | `SandboxSpec.timeout_s` / `.max_steps` / `.max_code_chars` / `.max_concurrency`；`ExecutionRecord.started_at` / `.ended_at` / `.duration_s` / `.termination_reason` |
| 状态与日志 | observation、exit code、状态差异 | `ExecutionRecord.observation` / `.exit_code` / `.state_diff` / `.memory_digest` |

## 2. 教程"可复现性五字段" → `SandboxSpec`

| 教程字段 | 我们要求明确的内容 | 自检 |
|:---|:---|:---|
| 镜像与依赖 | `image` + `deps_lock`（包 → 版本） | `gaps()` 报空 `deps_lock` |
| 权限边界 | `network`（默认 `False`）、`filesystem`（默认 `none`）、`tools` 白名单 | `gaps()` 报 `network=True` / `filesystem="workspace"` |
| 资源预算 | `timeout_s` / `max_steps` / `max_code_chars` / `cpu_limit` / `mem_limit_mb` / `max_concurrency` | `budget_fingerprint()` 单独哈希 |
| 重置策略 | `reset_policy` ∈ {`fresh`, `snapshot`, `persistent`} | `__post_init__` 直接拒绝非法值 |
| 日志与回放 | `log_fields` 必须含 `exit_code` / `termination_reason` / `state_diff` | `gaps()` 报缺失字段 |

`SandboxSpec.gaps()` 返回空列表 = 该合同已足以支撑"差异可归因于候选行为"的结论。
**默认合同 `DEFAULT_SPEC.gaps()` 恰好只报一条**（`deps_lock` 为空）——
这是诚实的状态：我们还没有冻结依赖版本。

### 两个指纹刻意分开

- `fingerprint()` —— **环境身份**：image / deps_lock / tools / network / filesystem / reset_policy / 验收条件
- `budget_fingerprint()` —— **资源预算**：timeout / steps / 代码体积 / CPU / 内存 / 并发

理由：把 timeout 从 30s 调到 60s，环境语义没变，说"环境变了所以不能比"是错的；
但它是必须记录的实验条件，所以另立一个指纹。`RunJournal.diff_against()` 同时返回
`same_env` 与 `same_budget`，由调用方决定是否归因。

## 3. `exit_code` 约定（贴 shell 惯例）

| termination_reason | exit_code | 触发条件 |
|:---|:---:|:---|
| `ok` | 0 | 正常产出动作 |
| `runtime_error` | 1 | 用户代码抛异常（含 `import os` 被拦、未知动作名） |
| `syntax_error` | 2 | `compile()` 失败 |
| `timeout` | 124 | 墙钟超限（与 coreutils `timeout` 一致） |
| `step_limit` | 125 | `sys.settrace` 行事件计数超限 |
| `no_action` | 126 | 代码跑通但没调 `action()`；或模型回复里没有代码块 |
| `tool_not_allowed` | 126 | `SandboxSpec.tools` 未授权 `action` 工具 |
| `code_too_long` | 127 | 超过 `max_code_chars` |

126 承担两种语义（都是"没有产出可执行动作"），用 `termination_reason` 细分；
调度器只看 exit code 即可决定"重试 / 换策略 / 放弃"，不必理解沙盒内部错误分类。

## 4. 三种重置策略

`SandboxSpec.reset_policy` 决定**下一步看到的 memory**：

| 策略 | 行为 | 对应教程的哪句话 |
|:---|:---|:---|
| `persistent`（默认） | memory 原地累积 | 与 Duck harness 的跨轮状态一致 |
| `fresh` | 每步清空 | "每任务新环境" |
| `snapshot` | 成功步记为检查点，失败步回滚到检查点 | "上一个任务是否污染当前结果" |

`Harness(reset_policy=...)` 可覆盖合同的默认值，但覆盖是显式的、会体现在 `SandboxSpec` 里。

## 5. Journal：先攒证据，再谈归因

```python
journal = RunJournal()
harness = Harness(llm=policy, journal=journal)
res = harness.run_episode(env, max_turns=60)

journal.failure_reasons()      # {'timeout': 3, 'no_action': 7}  —— 失败分布，不是总分
journal.success_rate()         # 0.83
journal.diff_against(other)    # {'same_env': True, 'attributable_to_policy': True, 'n_mismatch': 0}
```

`diff_against()` 只比较**剥掉时间戳**的字段（`ExecutionRecord.comparable()`），
所以同一环境跑两次同一策略，`n_mismatch` 应当为 0；不为 0 就说明有未建模的非确定性。
`attributable_to_policy=False` 时，禁止把两次运行的分数差异归因给候选策略 ——
这正是我们踩过的坑的可执行防线。

## 6. 用法

```python
from lingjing_solo.harness import Sandbox, SandboxSpec, RunJournal, Harness

spec = SandboxSpec(deps_lock={"numpy": "2.1.0"}, timeout_s=10.0)
print(spec.gaps())            # [] —— 合同完整
print(spec.fingerprint())     # 环境身份
print(spec.budget_fingerprint())

sb = Sandbox(spec=spec)
rec = sb.run_record("memory['n'] = 1\naction('UP')", SandboxContext())
rec.to_jsonl()                # 一行 JSON，可直接落盘
```

`Sandbox.run()` 仍返回旧的 `SandboxResult`（未污染：没有新增字段），
`Sandbox.execute()` 一次执行同时给出两个视图 —— **代码不会跑两遍**（有测试守着）。

## 7. 已知边界（别把它当安全边界）

1. **这不是隔离**。`type` / `object` 仍在 builtins 白名单里，
   `().__class__.__base__.__subclasses__()` 逃逸在原理上可行；`filesystem="none"`
   只是**声明**，我们没有真的挂载命名空间。真要跑不可信代码必须换
   子进程 + 容器/seccomp/nsjail。
2. **`state_diff` 是浅层差异**，只记键名不记值 —— 这是为了日志可比与不泄漏上下文，
   代价是"同一个键被改成什么"看不到，需要时得自己加显式 `log()`。
3. **`deps_lock` 尚未冻结**：`DEFAULT_SPEC.gaps()` 会一直报这一条，直到我们决定
   在 C-Local 里把 vLLM/torch 版本钉死。
4. **`cpu_limit` / `mem_limit_mb` / `max_concurrency` 只是声明字段**，
   当前沙箱是单进程内联执行，没有实际的 cgroup/rlimit 落点。
5. **`image` 是占位名**（`python:3.13-slim+sandbox-whitelist`），
   不指向任何真实镜像 —— 它进指纹是为了让"换了运行环境"这件事无法被悄悄忽略。
