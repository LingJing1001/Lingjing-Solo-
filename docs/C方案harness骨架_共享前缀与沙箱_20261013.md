## 3. ★ 核心不变量：共享前缀必须字节不变

容量模型给出的结论是：**前缀缓存值钱的不是省 prefill（只有 1% 量级），是省显存 ——
公共前缀只存一份 → 腾出显存 → 抬高并发 → 轮数变少。**

要把这条兑现，前缀必须满足：**同一局内 t=1..T 一致，且跨局一致**。
所以 `prompt.py` 把提示词**物理拆成两段**：`SYSTEM_PREFIX` 是模块级常量字符串，
构造后永不参与拼接；`build_prompt()` 只生成后缀。

已经被测试钉死的不变量：

```python
# tests/test_prompt_prefix.py
def test_prefix_is_invariant_across_graphs_turns_and_memory():
    p1 = build_prompt(A, turn=0).prefix
    p2 = build_prompt(B, history=[...], memory={...}, turn=999).prefix
    assert p1 == p2 == SYSTEM_PREFIX          # 跨帧、跨回合、跨局全部相同
```

为此刻意牺牲了几样"看起来更好"的写法：

- **不放回合号**（`t=3` 会破坏跨回合稳定性）→ 回合信息全部挪到后缀；
- **不放游戏名／局 id**（会破坏跨局共享）；
- **记忆只记录在文本末尾**，这样记忆膨胀不会顶掉前面的稳定段。

当前 `prefix_signature = 2d7840a5bd532727`（sha1 前 16 位）。
⚠️ **改动 `SYSTEM_PREFIX` 会让全部已缓存的 KV 块失效** —— 这正是为什么把它独立成常量、
并把签名暴露出来：改动成本要可见。

## 4. 对象图：平移不变身份 + 确定性渲染

真帧样例（`ar25_success_rep0` 末帧，13 个对象）：

```
FRAME 64x64 objects=13 adjacency=15
#0 c=9 n=1845 r=31 c=14 h=0c8e10b6d02c273c bbox=0,0-62,29 kids=[4]
#1 c=a n=189  r=31 c=31 h=96a0d778d82947bc bbox=0,30-62,32
#4 c=5 n=40   r=19 c=22 h=3aa6f56bd9a8405d bbox=15,18-23,26 kids=[6,7,8,9,10]
#6 c=0 n=1    r=16 c=19 h=275c644532791692 bbox=16,19-16,19
#7 c=0 n=1    r=16 c=22 h=275c644532791692 bbox=16,22-16,22
#8 c=0 n=1    r=16 c=25 h=275c644532791692 bbox=16,25-16,25
...
adj 0-1 0-4 0-12 1-2 1-12 2-3 2-5 2-11 2-12 3-12 4-6 4-7 4-8 4-9 4-10
```

注意 `#6/#7/#8`：**位置不同、hash 完全相同** —— 这就是平移不变身份的用处，
模型可以直接写 `[o for o in objects if o['hash']=='275c...']` 把"同一种东西"一次全捞出来，
不必靠坐标去猜。

三条设计取舍：

1. **原始数值网格刻意不进渲染**（对齐 Duck harness：模型看对象图，不看像素）。
2. **字段定序、无浮点、无 dict 迭代序** —— 渲染结果逐字节可复现，`graph_signature()` 给 sha1 便于断言。
3. **截断点也必须确定**：`max_objects=N` 时一律按 id 升序取前 N，并追加 `(+M more objects)`。

## 5. 沙箱：隔离边界要说清楚

`Sandbox.run(code, ctx)` 返回 `SandboxResult`（`ok / action / logs / memory / error / error_kind / duration_s / steps`）。

| 约束 | 实现 |
|---|---|
| builtins | **白名单**（不是黑名单）。无 `open/eval/exec/compile/input/globals/locals/vars/dir/getattr/setattr` |
| import | 自定义 `__import__`，只放行 21 个数学/集合/文本模块；无 `os/sys/socket/subprocess/pathlib/pickle/ctypes/threading/multiprocessing/importlib` |
| 超时 | `sys.settrace` 每条 line 事件查墙钟；超时抛 **`BaseException` 子类**，所以用户代码 `except Exception` 吞不掉 |
| 步数 | 同上，`max_steps` 兜住死循环 |
| 长度 | `max_code_chars` 兜住巨型代码块 |
| 状态 | 每次执行全新 globals；**只有 `memory` 跨回合持久**（同一个 dict 对象） |

**⚠️ 这不是安全边界，是接口契约。** `type` / `object` 仍在白名单里（模型常用），
所以 `().__class__.__base__.__subclasses__()` 这类逃逸在原理上可行。
上生产（跑不可信代码）必须换成子进程 + 容器/seccomp/nsjail。
本轮的目标是**把契约钉死，让上层逻辑先能在纯 CPU 上跑通**。

已经被单测覆盖的拦截行为：`import os/socket/subprocess`、`open()`、`eval/exec/compile`、
`while True: pass` 超时、`while True: pass` 步数上限、`action('CLICK')` 缺坐标、
`action('TELEPORT')` 未知动作、语法错、除零、未调用 `action()`。

## 7. 实测回填容量模型

脚本 `state/_harness_capacity.py`（原始输出 `state/_harness_capacity_out.txt`），跑 23 局真帧：

```
对象数      : min 14  中位 41  max 119
共享前缀    : 1136   （跨局一致，字节不变）
后缀        : min 287  中位 769  max 2057
单轮总上下文: min 1423  中位 1905  max 3193
```

### 7.1 共享前缀接入后

| 口径 | 并发 | 常驻 KV | 单轮秒 | 总分钟 |
|---|---|---|---|---|
| 未接入（旧：猜 0） | 39 | 468,000 | 27.05 | 74.4 |
| 接入（实测 1136） | 43 | 468,288 | 27.06 | **67.2** |

1.11× 提速。**比文档里那个"共享前缀 0→9000 给 3.9×"小得多** —— 因为真实前缀只有 1136 token，
不是 9000。这说明**上一轮那个 3.9× 是在 9000 token 的假设下算出的，属于乐观上限**。

### 7.2 ★ ctx 假设 12k 是浪费

| ctx_tokens | 并发 | 单轮秒 | 总分钟 | 判定 |
|---|---|---|---|---|
| 12000（旧假设） | 43 | 27.06 | 67.2 | OK |
| 8000 | 68 | 26.96 | 42.7 | OK |
| 6000 | 96 | 26.92 | 30.1 | OK |
| **4000（实测稳态）** | **164** | 26.98 | **18.0** | OK |
| 3200 | 228 | 26.99 | 13.0 | OK |

**ctx 12k → 4k：并发 43 → 164（3.81×），总耗时 67.2 → 18.0 min（3.74× 提速）。**

机制和共享前缀那一节是同一个：**ctx 变小 → 每路私有 KV 变小 → 并发抬上去 → 轮数变少**
（单轮耗时几乎不动，27.06 → 26.98 s）。之前 12k 的余量从未被用到，纯浪费显存。

### 7.3 上下文预算的真实量级

稳态（`history_tail=12` 封顶）单轮 ≈ **3293 token**，相对 `ctx=12000` 只用 **27.4%**。
把这个数当成算力的设计输入，比"猜 12k"靠谱一个量级。

## 9. 已知局限与下一步

1. **token 估算是字符启发式（≈4 字符/token）**，不是真 tokenizer。上线前要用目标模型的
   tokenizer（Qwen 系）复测一遍。量级判断不受影响，但"1136 vs 1080"这种差别不能当真。
2. **沙箱不是安全边界**（见 §5）。要跑不可信模型输出，必须上子进程 + 容器。
3. **`FakeLLM` 不看提示词**（直接从对象图算动作）。这是为了纯 CPU 可测；
   真模型接入时把 `LLMPolicy.complete(prompt, ctx)` 换成 vLLM 客户端即可，
   链路其余部分不用改。**但这也意味着"提示词写得好不好"目前还没有被验证过** ——
   下一次用真模型跑，第一件要看的就是"只给 prompt、不给 ctx，模型能不能自己算出动作"。
4. **未建模投机解码 / MTP**（llm-algo-leetcode 的 Task2）。按前缀共享这次的经验，
   它很可能是下一个量级杠杆。
5. **对象图在 119 个对象时后缀到 2057 token**。目前不截断。若真实游戏更复杂，
   要么提高 `max_objects` 的预算，要么改成"分层摘要"。
6. **还没接 `Env` 的真实适配**：官方 `is_done/choose_action` → `Env` 的薄层还没写
   （`kaggle_adapter.py` 里的是旧链路 `LingjingSoloAgent`，与这条旁路并列，未打通）。
