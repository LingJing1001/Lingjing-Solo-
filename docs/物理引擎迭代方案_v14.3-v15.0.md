### 关键架构问题：2D/3D 双轨

仓库里存在**两套场表示**：



* **3D 场**：`core/field.py`（Nx×Ny×Nz ndarray，Evacuation 场景用）

* **2D 场**：`core/phi.py` + `world_model/field.py`（64×64 网格，AR25/AR25 用，粗粒块统计，无真实场方程）

这两套**没有统一**。V14.3 的首要架构决策是：**让 2D 成为 3D 的一个切片（z=0 平面）**，而不是两套并行实现。

## 四、迭代路线图

### V14.3「场方程补全」—— 把扩散升级为完整场方程

**目标**：在不破坏守恒恒等式 `ΔΣφ = dt·ΣJ` 的前提下，给 `Field.apply_sources_and_evolve` 补上耗散项和自相互作用项。

**改动点**：



1. `core/field.py`**&#x20;— FieldConfig 加参数**



```
@dataclass
class FieldConfig:
    shape: tuple[int,int,int]
    h: float = 1.0
    D: float = 1.0           # 扩散系数（保留，向后兼容）
    gamma: float = 0.0       # 耗散系数 γ（v13.2 新增，默认 0 = 关闭）
    lam: float = 0.0         # 自耦合 λ（v13.2 新增，默认 0 = 关闭）
    phi0: float = 0.0        # 真空基线 Φ₀
    scheme: Scheme = "implicit"
```



1. `core/field.py`**&#x20;—&#x20;**`_evolve_explicit`**&#x20;补两项**



```
# 当前：dphi_dt = D·∇²φ + J
# V14.3：
lap = self._laplacian_volume(phi)
dissipation = -self.cfg.gamma * phi
self_interact = -self.cfg.lam * phi * (phi**2 - self.cfg.phi0**2)
dphi_dt = self.cfg.D * lap + dissipation + self_interact + J
```

> 注意：耗散项 −γφ 会破坏
> `ΔΣφ = dt·ΣJ`
> （因为它从场里抽走信息）。这是
> **预期行为**
> ——v13.2 里耗散是物理真实（熵增），守恒恒等式要修正为
> `ΔΣφ = dt·(ΣJ − γ·Σφ)`
> 。需要在
> `total()`
> 诊断里加 "耗散流失" 项。



1. `core/field.py`**&#x20;— 隐式求解器落地（M1 TODO）**

* 当前 `_evolve_implicit` fallback 到显式。V14.3 用 scipy 稀疏线性求解：

  `(I − dt·D·L + dt·γ·I) φ_new = φ + dt·J − dt·λ·φ(φ²−Φ₀²)`（自作用项显式，其余隐式）

1. **测试新增**（`tests/v14/test_field_terms.py`）

* C10：γ>0 时总信息量单调下降（耗散验证）

* C11：λ>0 时孤子解稳定（给一个初始孤子，跑 100 tick 形状不发散）

* C12：γ=0, λ=0 时与 V14.2 行为逐位一致（向后兼容）

* C13：修正后的守恒恒等式 `ΔΣφ = dt·(ΣJ − γ·Σφ)` 机器精度

**验收标准**：



* 现有 444 测试不破坏（γ=0, λ=0 默认关闭）

* 新增 4 项契约测试全过

* Evacuation 场景在 γ=0.1, λ=0.01 下仍能完成疏散（不发散）

### V15.0「多 Agent 共识与 L4」—— 从单 Agent 到多 Agent 物理环境

**目标**：把协议 6 的 R1–R5 真正建起来，让多 Agent 在同一场上无通讯共识；C 值作为只读监视器接入 tick 循环。

**改动点**：



1. `core/consensus.py`**（新建）— 统一提交队列**



```
class ConsensusLayer:
    """协议 6：R1-R5 无通讯共识。"""
    def __init__(self, field: Field):
        self.field = field
        self.version = 0
        self.action_queue: list[AgentWriteback] = []

    def read_snapshot(self, agent_id: str) -> WorldState:
        """R1/R2：所有 Agent 读同一个 V_N。"""
        return self.field.phi.copy()

    def submit_action(self, agent_id: str, wb: AgentWriteback):
        """R3：Action 入队，不立即写场。"""
        self.action_queue.append(wb)

    def tick(self) -> int:
        """R4/R5：统一求解，V_{N+1} = V_N + 1。"""
        J_total = sum(validate_writeback(wb, self.field.phi.shape)
                      for wb in self.action_queue)
        self.field.apply_sources_and_evolve(J_total, dt)
        self.action_queue.clear()
        self.version += 1
        return self.version
```



1. `core/engine.py`**&#x20;— Engine.step 改造**

* 当前：Agent 决策 → apply\_action → 立即聚合 → 演化

* V15.0：Agent 决策 → submit\_action（入队）→ 全部提交后 → consensus.tick () 统一演化

* 这保证 "写入顺序无关"（加法交换律）

1. `core/types.py`**&#x20;— C 值接入**

* `TickRecord` 加 `c_value: float` 字段

* 每 tick 结束时，`sica.compute_c_value(field.phi, agents)` 只读计算，不写场

1. **多 Agent 场景**

* 写第二个场景：`CollaborationScenario`（2-3 个 Agent 推箱子，对照 v13.2 的 3Agent+1 门 + 1 箱 Demo）

* 验收：3 个 Agent 在同一 tick 各自决策，最终场状态与提交顺序无关（1000 次随机顺序测试）

**验收标准**：



* 1000 次并发写入顺序无关测试 100% 通过

* 离线 Agent 重连后只读一次 `read_snapshot()` 即追上（不需要补消息）

* C 值在每 tick 可观测，但不影响场演化（只读）

## 五、2D/3D 统一决策（V14.3 前置）

在开始 V14.3 之前，先做一个架构决策：

**方案 A（推荐）**：2D 场是 3D 场的 z=0 切片。



* `world_model/field.py` 的 64×64 网格 → `FieldConfig(shape=(64,64,1))`

* AR25 的 2D 操作自动变成 3D 的薄切片操作

* 好处：一套场方程、一套 Laplacian、一套守恒逻辑

**方案 B**：保留两套，加适配层。



* 2D 和 3D 各自演化，通过 `adapter.py` 互转

* 好处：不动现有 AR25 代码；坏处：长期维护两套

**建议选 A**，在 V14.3 第一个 PR 里完成迁移，后续所有物理项只在 3D 场上实现。

## 七、风险与诚实边界



1. **耗散项破坏守恒恒等式是预期行为**，不是 bug。需要把 `ΔΣφ = dt·ΣJ` 修正为 `ΔΣφ = dt·(ΣJ − γ·Σφ)`，并在诊断里区分 "源项注入" 和 "耗散流失"。

2. **自相互作用项 λΦ(Φ²−Φ₀²) 是非线性的**，显式积分可能不稳定。V14.3 先用 "显式处理非线性项 + 隐式处理线性项" 的半隐式格式，不追求全隐式。

3. **度规张量 g\_μν 是 4×4×N³ 的大数组**，内存开销是 Φ 的 16 倍。V14.4 先只算对角元（g\_00, g\_11, g\_22, g\_33），非对角元后续再加。

4. **多 Agent 共识在 Solo 单 Agent 架构里是新增能力**，不是修复。V15.0 之前所有测试都是单 Agent 的，不要假装已经支持多 Agent。

5. **8 个 torch 依赖测试未跑**，AOP 神经网络相关的物理（如 learned world model）不在本方案范围内。

6. **CUDA 不在 V14.3-V15.0 范围**，等 N≥128 规模上来再做（V14.2 已明确披露）。
