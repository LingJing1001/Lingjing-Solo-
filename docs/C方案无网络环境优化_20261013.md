# C 方案｜无网络比赛环境的适配与优化（2026-10-13）

> 触发：用户指出「正式比赛是没有网络的，你看看怎么优化」。
> 结论先说：**无网络本身没让提交崩，但它让一个更隐蔽的问题暴露出来 ——
> 提交包一直在"静默少跑一半能力"。**

---

## 1. 比赛的执行模型（从 notebook 实证，不是推测）

`integrations/ARC-AGI-3-Kaggle-Starter/notebooks/submission.ipynb` 的第 5 个代码单元
把拓扑写得很清楚：

```
┌─────────────────────── Kaggle 容器 ───────────────────────┐
│  enable_internet = false   →  出不了公网                    │
│  /kaggle/input/competitions/.../arc_agi_3_wheels           │
│                            →  赛方挂载 wheel，供离线 pip    │
│  /kaggle/input/competitions/.../ARC-AGI-3-Agents           │
│                            →  赛方挂载框架（含 agents 包）   │
│  environment_files/        →  25 个游戏源码，本地就有        │
│  gateway:8001              →  容器内**边车**，喂环境 + 记分  │
└────────────────────────────────────────────────────────────┘
```

三个推论，前两个都很容易搞错：

1. **"没网络" ≠ "没 HTTP"**。官方 `main.py` 用的是
   `OPERATION_MODE=online` + `ARC_BASE_URL=http://gateway:8001/`，
   走的是容器内边车。所以护栏的**放行名单**必须是
   `gateway / localhost / 127.0.0.1 / ::1`，全禁的话连游戏环境都拿不到。
2. **构建期能上网，运行期不能**。本机 `OperationMode.NORMAL` 实测能拉到 25 个环境。
   所以在本地验证"离线能不能跑"必须**显式** `mode="offline"`，否则测的是联网路径。
3. **任何运行期下载都是致命的**。`from_pretrained` / HF hub / pip 全部不可用。
   权重只能来自 `model_sources` 挂载的只读输入目录。

另外确认了两个"好消息"：`environment_files/` 里 **25 个游戏全部本地化**
（`find environment_files -name metadata.json | wc -l` = 25），且 `arc-agi` 的
传递依赖（`arcengine` / `matplotlib` / `pillow` / `pydantic` / `requests` / `flask`）
都由赛方 wheel 覆盖 —— 离线 pip 是通的。

## 2. 真正的发现：提交包在**静默降级**

`agent/my_agent.py` 把可选能力全写成 `try: import X / except: 降级`。
这种写法**不会崩**，所以缺文件在比赛里表现为"能力悄悄消失"，
而不是报错 —— 这才是"本地验证过的分和线上分对不上"的机制。

用导入闭包审计（`lingjing_solo/harness/offline.py`）比对
"agent 真正要什么" vs "notebook 实际内嵌什么"：

| 能力 | 模块 | 修复前 | 修复后 |
|---|---|---|---|
| 引擎求解器（读游戏源码搜解） | `lingjing_solo.engine_solver` | ✗ 静默降级 | ✓ |
| 引擎动作适配 | `lingjing_solo.harness.engine_action_adapter` | ✗ 静默降级 | ✓ |
| 闭卷 AR25 求解器 | `lingjing_solo.closed_book.ar25_solver` | ✗ 静默降级 | ✓ |
| 闭卷 TU93 求解器 | `lingjing_solo.closed_book.tu93_solver` | ✗ 静默降级 | ✓ |
| 点击候选重排 | `lingjing_solo.perception.stability` | ✗ 静默降级 | ✓ |
| AOP 控制器 | `lingjing_solo.neural.aop_controller` | ✗ 静默降级 | ✓ |
| FT09 求解器 | `lingjing_solo.exploration.ft09_solver` | ✗ 静默降级 | ✓ |
| 通用 shadow 搜索 | `lingjing_solo.planning.search.generic_shadow` | ✗ 静默降级 | ✓ |
| **点击热图** | `arc_adaptor.click_heatmap` + 权重 | ✗ 双重缺失 | ✓ |
| AOP 检查点 | `data/aop/collected_10eps.pt` | ✗ | ~ 有意不发（见 §6） |
| SU15 兜底求解器 | `su15_solver` | ✗ | ~ 有意不发（见 §6） |

共 **8 个模块 + 1 个外部包 + 1 个权重文件**。热图那条最典型：
`arc_adaptor/click_heatmap.py` 里权重默认路径是硬编码的
`F:/pro2/state/click_heatmap_v3.npz`（本机路径），
`CLICK_HEATMAP_WEIGHTS` 也没在提交里设置 ——
**包没带、权重也没带、环境变量也没指**，三重缺失。

## 3. 根因：打包器的收录集合是**手写的**

`scripts/build_notebook.py` 原来有一份 5 项的硬编码 `roots`：

```python
roots = {                                    # ← 随代码增长必然失准
    "lingjing_solo", "lingjing_solo.core", "lingjing_solo.perception",
    "lingjing_solo.transfer.ceax_controller", "lingjing_solo.arc_transition",
}
```

`engine_solver` / `closed_book.*` / `neural.aop_controller` /
`planning.search.generic_shadow` / `perception.stability` 都不在这份清单里，
于是被静默丢掉。而 `arc_adaptor` 在 `lingjing_solo/` **之外**，
打包器只收 `lingjing_solo.*`，结构上永远带不上。

另外还有两个隐藏坑，都是修复过程中被探针逼出来的：

- **中间父包漏收**。只收叶子文件会得到"没有 `__init__.py` 的中间目录"。
  `planning/search/__init__.py` 还真身会在导入期用**文件路径**去加载被目录遮蔽的
  兄弟文件 `planning/search.py`，于是探针报
  `FileNotFoundError: .../planning/search.py`。
- **`harness/__init__.py` 真身是个黑洞**。它第一行就是
  `from .kaggle_adapter import ...`，而后者 import `..agent`
  → `planning/discrete_nav` → `ls20_solver` → 整条 agent 栈。
  闭包里其实只需要 `harness.engine_action_adapter` 一个文件。

---

## 4. 修复方案（已落地）

### 4.1 收录集合改为**由真实导入闭包推导**

- 种子来自 `agent/my_agent.py` 的 import（含惰性/受保护导入）；
- **祖先包一并收录**，且继续跟进它们自己的 import；
- 收尾用**同一套闭包**校验（`_verify_packaging`），缺一个就 `ABORT`，
  不允许"能过就过"。

### 4.2 新增"外部包"与"资产"两条独立通道

- `EXTRA_ROOTS = ("arc_adaptor.click_heatmap",)` —— 只取其闭包（**1 个文件 8.7 KB**，
  不整包搬：整包 45 文件 463 KB 会顶穿配额）。
- 外部包写到 `/tmp/lj_ext/<pkg>/`，并在 run 单元 `cp -r` 到 `/kaggle/working/`
  —— 那里正是 `my_agent._ensure_adaptor_on_path()` 探测的 `parents[3]`。
- `ASSET_FILES` 把**小**资产以 base64 内联到 `/tmp/lingjing_solo/assets/`，
  与 `offline.OFFLINE_ENV["CLICK_HEATMAP_WEIGHTS"]` 的默认值对齐；
  总 base64 有预算上限（128 KB），超了直接 `ABORT` 逼作者改走 `dataset_sources`。

### 4.3 三个重 `__init__.py` 换极简替身

`planning/__init__.py`、`planning/search/__init__.py`、`harness/__init__.py`
换成空替身。理由分别是：闭包里没人用 `planning` 的根级 re-export；
`search/__init__` 的 `_load_legacy_engine()` 是一条脆弱链；
`harness/__init__` 会拖进整条 agent 栈。**代价写在替身 docstring 里**：
提交包里只支持子模块导入。

### 4.4 体积：从"顶穿上限"压回安全区

收录集合一改，payload 立刻从 105 → 121 个文件，Kaggle 计量体积
**1,130,037 B > 1,048,576 B 上限**。继续删模块腾空间就是回到老路，
所以只能从注释和 **docstring** 里省：

- 原有 `_strip_comments` 只删 `#` 注释；
- 新增 `_blank_docstrings`：把 docstring 的字符清掉，但**一行都不删**
  （行号必须保持 —— agent 里到处是 `file:line` 引用，比赛日志只给行号）；
- 若 docstring 就是整个函数体，该行补 `pass`，否则会变成 `IndentationError`；
- 每步都用 `_ast_dump_sans_docstrings` 双向比对，**语义变了就 ABORT**。

结果：压掉 **175,137 字符 / 119 个文件**，
Kaggle 计量 **923,913 B**，余量 **124,663 B**。

另确认无代码依赖 docstring：全仓只有
`arc_adaptor/agents/strategies/run_vc33_r234.py` 用 `__doc__` 做 argparse 描述，
而它**不在**闭包内（只带 `click_heatmap`）。

## 6. 有意不发货的两项（记录，不是疏漏）

审计特意把这两项单列成"已接受（有意不发货）"，避免下次分不清
"漏了"和"放弃的"：

| 项 | 理由 |
|---|---|
| `su15_solver` | 仓库根单文件，只在内联 `_SU15_PLANS` 不全时才走；它还要 `environment_files/su15/<hash>/su15.py` 上 sys.path，打包成本高、收益只覆盖兜底路径。**主路径（内联计划）已随包**。 |
| `aop_checkpoint`（288 KB） | base64 内联会顶穿 1 MiB 源码上限，要启用须走 `dataset_sources`。 |

## 7. 无网络下**做不到**的事，以及唯一合规的 LLM 路径

- 远程 LLM API：**不可能**（无外网）。
- 运行期下载模型：**不可能**（HF hub / pip 均不可达）。
- 本地跑开源权重：**可行，但只有一条合规路径** ——
  `kernel-metadata.json` 的 `model_sources` 挂 Kaggle Model（只读输入），
  同时 `enable_gpu: true` 拿 RTX 6000（g4-standard-48 / 96GB），
  再配 `apply_offline_env()` 的 HF/vLLM 离线开关做本地推理。

需要一起改的元数据（当前是纯规则 agent）：

```jsonc
{
  "enable_gpu": true,                      // 现在 false
  "enable_internet": false,                // 保持
  "model_sources": ["<owner>/<model>"],    // 现在 [] —— LLM 的唯一通道
  "dataset_sources": ["<owner>/<assets>"]  // 现在 [] —— 大资产（如 AOP 检查点）
}
```

`enable_gpu` 的取值由 `build_notebook.ACCELERATOR` 决定（现在 `"cpu"`，
`main()` 会把 `enable_gpu=false` 同步回元数据）。要上 GPU 就改成 `"rtx6000"`。

## 9. 已知边界

- **审计只覆盖"文件在不在"**，不验证"逻辑对不对"。载荷能 import、
  热图能出提议，但**提示词质量、求解器正确性未被本轮的探针覆盖**。
- `_blank_docstrings` 依赖"行号不变"，所以**不压缩单行 `def f(): "..."`
  形式的 docstring**（会毁掉定义），这类会被跳过。
- 打包器对替身文件是"**按真身跟依赖、按替身发货**"（保守超收）：
  会把替身真身里用到、但替身后用不到的模块也带进去（如
  `planning/advisor.py`），换来的是"不会因为替身漏依赖而崩"。
- `OfficialEnv` 的 reward 仍是推断值，**不是官方 RHAE 计分**，出分必须走 scorecard。
