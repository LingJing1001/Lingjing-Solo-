## 3. 为什么零效果：补丁**确实生效了**，但不在关键路径上

### 3.1 补丁被调用了（插桩证据）

给 after 快照插桩（`agent/_probe_afterB_percclick.py`，只在 `_perc_click_candidates` 里追加写日志），
canned 关键 3 局：

```
CALL 次数: 40        ← 函数被调用 40 次（3 局 × 400 步）
RANK 次数: 40        ← 新排序器每次都成功返回（n=4/out=4），零异常回落
```

（tables 口径关键 3 局同样是 CALL 40 / RANK 40 —— 两种口径下调用量完全一致，且都无异常回落。）

### 3.2 补丁**改变**了实际点击坐标（关键证据）

bench 日志里的 `hybrid-click … src=perc click=(x,y)` 就是这条腿真正下手的位置。
tables 全量 25 局里它一共出手 **27 次**，前后对比**每一次坐标都变了**：

| 局 | before 快照 | after 快照 |
|---|---|---|
| `cn04` | **`(31,31)`** | `(25,43)` |
| `dc22` | `(15,31)` | `(15,34)` |
| `ka59` | **`(31,31)`** | `(16,31)` |
| `lf52` | `(31,32)` | `(33,29)` |
| `m0r0` | `(31,33)` | `(23,39)` |
| `sk48` | `(31,26)` | `(29,26)` |
| `sp80` | `(31,30)` | `(21,17)` |

`(31,31)` 是 **64×64 屏幕正中心**——`cn04`/`ka59` 在 before 下点的就是纯色背景的 bbox 中心，
正是镀铬偏差的典型指纹；其余几个也都紧贴中线（col 30~33），同样是"大背景块中心"。
**after 下这些全被挪开了。**

所以**感知层面的修复是真的、且普遍生效**：7 个局、27 次出手，坐标无一例外被改写。

### 3.3 但结果不变

两个原因叠加：

**① 出手次数太少、且不在关键路径上。** tables 全量 25 局只出手 27 次，且集中在 `step=0~4`
（`dc22/ka59/lf52/m0r0/sp80` 各 5 连击，`budget=13` 的探路枪）和 `step=20`（`cn04`/`sk48` 各 1 次）。
之后 agent 立刻回到 CEAX 主导的路径（`ceax_undo` / `ceax_hybrid_walk` / `ceax_arrange`…），
**一枪探路点的差别不足以改变 400 步的结局**。

**② 点击主渠道是 CEAX，根本不走这条腿。** canned 关键 3 局 1200 步里 `ACTION6` 总共只有 11 次，
来源是 `ceax_arrange`(10) / `ceax_chrome_end`(1)，坐标由 CEAX 直接给出（如 `ceax_arrange:(27,54)`），
**完全不经过 `_perc_click_candidates`**。

## 4. 那 +1 / +2 关是谁的功劳

对比 `git show HEAD:…/my_agent.py` 与 before 快照，**忽略空白差 94 行**，多出来的是并行会话的改动，其中与增益直接相关的是：

- `if _CLOSED_BOOK and gid == "ar25":` → `_ar25_cb` **ar25 闭卷引擎求解器**（`_ar25_frame_solver` / `_ar25_pick`）
- `_SU15_PLANS` / `self._su15_plans` **su15 inline 计划**
- `_ENGINE_SOLVER_GAMES` 门控

三份基线产出时间：canned `12:40`、tables `13:24`、strict `14:31`（本地时）；before 快照取自 `15:28`。
**ar25 在 tables 口径下 0→1 关，正是 `_ar25_cb` 的功劳**（tables 是 CB=1，该求解器生效）；
canned 的 `cn04 2→3` / `sk48 0→1` 同理。B 与此无关。

## 5. 对后续的意义

- B 可以**保留**（无回归、无风险，且修掉了一个真实的感知缺陷），但**不要指望它涨分**。
- 本地 benchmark 里"点击决策"的主渠道是 **CEAX**（自带坐标）与 **inline 计划**，
  感知腿只在 `hybrid-click` 探路时各出 1 枪。**要让感知腿变成关键路径，得先让它接管 CEAX 的点击坐标**，
  或者走 Option C（LLM + REPL harness）让模型直接消费分割/镀铬信息。
- 方法论教训：**已提交基线会过期**。凡是拿"新代码 vs 旧 JSON"当 A/B，都必须先补一组
  "旧代码在本机重跑"的对照，否则会把别人的改动算在自己头上。
