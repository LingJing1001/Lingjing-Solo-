## 2. 验证方法论（我们用什么验）

团队统一口径见 `docs/最小可运行闭环_团队统一集成与跑测验证方法.md`：

```text
recording → replay → verification report
     │
     ├─ Simulator evidence（离线引擎）
     ├─ Offline engine evidence（clone 回放）
     └─ Live/Scorecard evidence（官方计分）
```

**三层证据不可混用**：模拟器通过 ≠ 离线 WIN ≠ Kaggle 上榜。

## 4. 外部论文对照

### 4.1 ARC-AGI-3 _executable world model_ 线（最相关）

| 论文 | 核心观点 | 与我们的关系 |
|------|----------|--------------|
| **Rodionov (2026)** [Executable World Models for ARC-AGI-3](https://arxiv.org/abs/2605.05138) | 可执行 Python 世界模型 + **replay verification** + 简化 + 规划；GPT-5.5 下 **15/25 全通**，mean RHAE **58%** | 我们的 plan contract、route 3× replay、`_wa30_validate_plan` **同范式**；我们缺「agent 自写 executable model」 |
| **Rodionov ablation (2026)** [Do Coding Agents Need EWM...?](https://arxiv.org/abs/2607.15439) | 四变体 ablation：**verification  treatment  consistently ranks first**；executable alone 不总是有益 | **强支持**我们的「验证 > 模型」优先级；AOP authority 未过 holdout 前不应启用 |
| **Tycho (2026)** [Active Abstraction with Programmatic World Models](https://arxiv.org/html/2607.28287v1) / [GitHub NIMI-research/Tycho](https://github.com/NIMI-research/Tycho) | Observe → model → act → revise；programmatic hypothesis 可 inspect/edit/verify | 与 R2–R5 闭环 + CEAX 同精神；Tycho 更强调 **agent 自诱导** 模型 |

**文献对框架的校验**：

1. ✅ **Replay verification 是 ARC-AGI-3 有效 Agent 的核心** — 我们已有 route replay、plan validate、recording gate  
2. ✅ **Verification 优先于 raw modeling** — 支持 AOP shadow、fail-closed、禁止未校准控盘  
3. ⚠️ **Executable world model 自写** — 我们主要是 **人工校准 plan**，不是 agent 运行时归纳 executable model  
4. ⚠️ **Public set 饱和 ≠ generalization** — 论文明确警告；我们的 7 WIN 仅在 public 25 局

### 4.2 世界模型 + epistemic uncertainty（AOP 理论依据）

| 论文 | 核心观点 | 与 AOP 的关系 |
|------|----------|---------------|
| **E-MCTS** (TU Delft) | 规划时传播 **epistemic uncertainty** | 支持「不确定性应进入 planning」，非仅 EMA 点估计 |
| **Knowledge Boundary** (AAAI) | Ensemble disagreement 作 intrinsic reward + 过滤不可靠 rollout | 支持 AOP **否决/排序** 而非 **直接选动作** |
| **Model-Value Inconsistency** (ICML) | 模型-价值不一致作 epistemic 信号 | 可未来对接 `field.py` 冲突检测 |
| **Bayesian / Value-Distributional MBRL** | 区分 aleatoric vs epistemic | 支持 AOP 标签三分；当前 MLP 只是第一步 |

**文献对 AOP 的校验**：

1. ✅ 「动作效果 + 不确定性 → 探索/过滤」方向 **正确**  
2. ❌ 当前 16 维 MLP + CE **不等于** 文献中的 ensemble/Bayesian epistemic  
3. ✅ **低置信回退确定性 planner** 与文献 robust planning 一致  

### 4.3 与 NIFTy 叙事的关系

NIFTy（Likelihood / Model / optimize_kl）在对话中被提议为 **后验推断工具**。

| 项 | 状态 |
|----|------|
| 问题定义（缺方差/置信度） | ✅ 与 `field.py` 差距分析一致 |
| 代码实现 | ❌ 仓库无 NIFTy 依赖或调用 |
| 合理定位 | **研究远期**；近期用 AOP MLP + calibration 更现实 |

## 8. 最终判定

### 8.1 什么被验证了

- **验证方法论本身**：与 2026 ARC-AGI-3 顶会论文 **高度一致**（replay、verification、plan executor、fail-closed）
- **R2–R5 + plan contract + recording gate**：单元与集成测试 **通过**
- **SmartRouter 确定性路线**：**7 WIN** 实证，路线回放 **9/9 通过**
- **AOP 数据契约与 shadow 接入**：**符合** MBRL uncertainty 文献的「辅助层」定位

### 8.2 什么还没被验证

- **世界模型 epistemic 层**：EMA 无 holdout；AOP 无 calibration report
- **NIFTy / 贝叶斯后验**：纯 roadmap
- **hidden / private 集泛化**：无 sealed eval
- **相对 SOTA**：7 WIN << Rodionov 15 WIN（不同 agent 类，但差距真实）

### 8.3 对「理论是否正确」的回答

> **框架的理论方向与当前 ARC-AGI-3 研究主流一致，且内部验证规则设计合理；**  
> **竞赛层面的有效性已被 7 WIN 部分证实，但未达到 executable-world-model SOTA；**  
> **不确定性/AOP/NIFTy 部分属于正确的问题定义 + 未完成的实现，不应表述为已验证能力。**
