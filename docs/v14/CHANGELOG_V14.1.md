# 灵境引擎 V14.1 变更记录

> **版本主题**：从「研究原型」转向「可信底座」——把"能跑"变成"有契约守护的能跑"。

## 本版核心改动

### 1. 契约测试层（新增 `tests/test_contracts.py`，6/6）

由 `diagnose.py` 真实运行结果固化。每个测试对应一条可观测的物理/工程契约：

| ID | 契约 | 实测证据 |
|----|------|---------|
| C1 | 零通量边界纯扩散守恒 | ΔΣφ = 0（机器精度） |
| C2 | 守恒恒等式 ΔΣφ = dt·ΣJ | rel = 5.55e-16 |
| C3 | Agent 真实连续位移 | 4/4 移动 |
| C4 | 疏散闭环（向出口 + 撤离） | 12/12，质心 10.6→1.18 |
| C5 | 确定性（同 seed 复现） | True |
| C6 | 面积律泡壁恒定 O(R²) | N=12→30，M 恒=123 |

### 2. 场景插件接口自检（新增 `core/scenario.py::validate()`）

**动机**：`Scenario.observation` 抽象签名（2 参数）与引擎实际调用（3 参数含 `all_agents`）长期不一致。
此前属于"测试套件结构性盲区"——只有运行时才暴露。

**机制**：`Engine.__init__` 自动调用 `scenario.validate()`，检查：
- `observation` 签名能接收 `(field, agent, all_agents)`
- 必要属性 `exits` / `shape` 存在

签名错误 → **构造时立即报错（fail-fast）**，而非疏散跑到一半崩溃。

### 3. 统一回归入口（`regress.py`）

分层明确：契约层 / 集成层 / 平台层。有序去重，退出码可用于 CI。

## 关键诚实修正（重要）

> **上轮（V14.0 收尾对话）中"test_e2e FAILED: Agent did not move"的诊断是错误的。**

真实情况：
- 该失败来自**诊断脚本自身用了过时 API**（`FieldState`、`hist['com']`、`sc.bubble.active`），
  并非引擎缺陷。
- **对接现行 API 的 `tests/test_e2e.py` 一直是 7/7 全绿**，包括
  `质心 19.25→0.55`、`21 tick 全部撤离`、`拥挤减速`、`软分离`、`确定性复现`。
- V14.0 的疏散闭环**原本就是通的**。本轮通过 `diagnose.py` 裸跑 + `validate()` 自检
  **双重独立验证**确认。

**教训**：诊断工具的 API 假设必须与源码同步核对；工具报错不能直接算到引擎头上。

## 接口自检的独立验证

`tests/test_scenario_contract.py` 用一个**故意写错的场景**（`observation(self, field, agent)`，缺 `all_agents`）
验证 `validate()` 确实能拦住它，并给出明确改法。第一版检查条件写反（参数数 `< 3`）
被该测试当场抓出并修正——**自检机制本身也有测试守护**。

## 诚实边界（持续有效）

- ✅ 守恒达到机器精度（零通量边界完美守恒）
- ✅ 疏散物理闭环真实可用（12/12 撤离、拥挤/排斥/反射全部生效）
- ✅ 面积律：泡壁节点恒定 123 = O(R²)（R=3 固定，与 N 无关）
- ⚠️ N≤30 小规模下加速比受 CSR 常数开销影响；百倍加速需 CUDA 或更大 N
  （面积律是**数学事实**，已用 M-恒定实测确认；工程加速比待规模扩展）
- ⚠️ L4 意识层未实现（按 IFC 文档 §7.1.1，L0-L3 已足够工程落地）
