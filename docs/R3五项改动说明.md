## 2. 逐项详解

### 2.1 CEAX 关卡重置

**问题**：CEAX 在关卡切换时不重置内部状态，导致旧关卡的技能/策略残留，新关卡无法正确探索，表现为卡在 L1 无法推进。

**方案**：在 `levels > self._levels_seen` 时调用 `self.ceax.reset_game()`，同时清空 `_prev_grid`。

**代码位置**：`examples/my_agent.py:330-337`（`_choose_action_inner()` 的 level 检测段）。

```python
if levels > self._levels_seen:
    self._levels_seen = levels
    self.ceax.reset_game()
    self._prev_grid = None
    print(
        f"[{BUILD_TAG}] ceax-reset L{levels} (level transition)",
        flush=True,
    )
```

**验证（2026-09-21 本机）**：⚠️ **只有代码级，没有行为证据**。本机环境目录只有 `ls20` / `ar25` / `sc25` 三个（`environment_files/` 与 ARC checkout 各一半），lp85、su15 **跑不了**；而唯一能跑的未知局 sc25 一路停在 `levels=0`，`levels > _levels_seen` 恒假 ⇒ 这一支**一次都没进过**（实测日志 `ceax-reset` 命中 0 次）。改动前后 sc25 都是 0 关 / 800 步，ls20 309、ar25 276 逐关步数逐项不变。要拿这条当结论，必须到有 lp85/su15 的机器上补跑。

### 2.3 R3 通用状态搜索

**问题**：原 R3 搜索仅适配 ar25（`arc_shadow.py` 中的 ar25 专用 snapshot/restore），对其他未知游戏无法使用，错失搜索提分机会。

**方案**：
1. 新建 `lingjing_solo/planning/search/generic_shadow.py`，提供通用快照/还原/状态键函数。
2. 在 `my_agent.py` 中，对非 ls20/ar25 且含 ACTION5 的游戏，尝试调用 `r3_generic_search()`，限时 12 秒、最多 15000 节点。
3. 搜索成功则按路径依次执行动作；失败则静默回退 CEAX。

### 2.4 Hybrid-click 策略

**问题**：部分游戏同时提供键盘动作（ACTION1–4）和点击动作（ACTION6），CEAX 默认倾向键盘动作，但某些关卡需要先点击清除障碍物才能推进，导致 11 个零分场景。

**方案**：
1. 检测 `valid_actions` 同时含 ACTION6 和 ACTION1–4。
2. 对分割出的物体，选像素最多的物体，计算其中心坐标。
3. 在前 20 步内优先发出 ACTION6 点击该中心。
4. 预算耗尽后回退 CEAX 正常决策。

**代码位置**：`my_agent.py` `_choose_action_inner()` 中 hybrid-click 段。

```python
has_click = "ACTION6" in valid
has_keyboard = any(a in valid for a in ("ACTION1", "ACTION2", "ACTION3", "ACTION4"))
if has_click and has_keyboard and self._hybrid_click_budget > 0 and objects:
    best_obj = max(objects, key=lambda o: len(o.pixels))
    cx = (best_obj.bbox[0] + best_obj.bbox[2]) // 2
    cy = (best_obj.bbox[1] + best_obj.bbox[3]) // 2
    self._hybrid_click_budget -= 1
    action = GameAction.ACTION6
    action.set_data({"x": int(cx), "y": int(cy)})
    return action
```

**验证（2026-09-21 本机）**：⚠️ **触发属实，提分无据**。sc25（`keyboard_click`）上 20 步预算全部用掉、日志确实出现 `hybrid-click` 行；但那 5 行（打印节流 `my_agent.py:403`：`step<5` 或 `%20==0`）显示**每次点的是同一坐标 `(30,31)`、目标物体像素数恒为 3457**——即"最大物体"在这局上是个不动点，20 次点击没有差异化。整局 800 步仍 `levels=0`。所以"零分场景减少、总分提升"这句**本机证不了**，需要能推进的混合局才有资格说。

> 上面片段与实际实现差一个守卫：码里还要求 `gid not in ("ls20", "ar25")`，即**已知局不会被它抢方向盘**（否则 ls20/ar25 的地板就没了）。这段是节选，不是全文。

### 2.5 ft09 INLINE 集成

**问题**：ft09（翻转块谜题）是纯点击游戏，CEAX 对其几乎零分；在线求解器 `Ft09Solver` 依赖 `env._game`，线上不可用。

**方案**：采用与 ls20/ar25 相同的"锁地板"策略——离线预解 + 硬编码：
1. `_FT09_HARDCODED`：L0–L7 的预解点击坐标（显示坐标），每个坐标对应一次 ACTION6 点击。
2. `_ft09_solve_online()`：优先查硬编码表；若当前 level 不在表中且 `_env_ref._game` 可用，则调用 `Ft09Solver` 在线求解（模型法 + BFS 回退）。
3. 执行时按 `_ft09_idx` 依次发出 ACTION6 + (x, y) 数据。

**代码位置**：`my_agent.py` 中 `_FT09_HARDCODED` 常量 + `_ft09_solve_online()` 方法 + `_choose_action_inner()` 中 ft09 分支。

```python
_FT09_HARDCODED: dict[int, list[tuple[int, int]]] = {
    0: [(6, 6), (14, 6), (22, 6), (6, 14), (14, 14), (22, 14), (6, 22), (14, 22), (22, 22)],
    1: [(6, 6), (22, 14), (14, 22)],
    # ... L2–L7
}
```

**⚠️ 注意**：当前硬编码坐标为占位值（基于 ft09 典型 3×3 块布局估算），需要跑测后用真实通关序列替换，校准流程与 ls20/ar25 一致。

**验证（2026-09-21 本机）**：❌ **零验证，本机也验不了**。`F:/pro/Lingjing-Solo-/environment_files/` 只有 `ar25`，`F:/pro/ARC-AGI-3-Agents/environment_files/` 只有 `ls20`、`sc25-635fd71a`；全盘 `find -maxdepth 4 -iname 'ft09*'` **0 命中**——本机没有 ft09 环境包，那 8 条占位坐标**一次都没有跑过**。另外 `_ft09_solve_online()` 的在线求解回退需要 `env._game`，线上必然走不到（见 §5），所以线上唯一可能就是这张硬编码表本身。推之前要么拿到 ft09 环境校准，要么在提交说明里明确写"未校准占位值"。

## 6. GitHub commit `2124d6e7e22cf1df6afdcf723c8645a1eb98f72b` 增量复核（2026-09-22）

该 merge commit 的 R3 增量不是“搜索已经可用”，而是把失败原因从静默失败改成可审计信号：

- `generic_shadow.py` 去除 AR25 专属状态/胜利探测，改用通用快照编码、`(snapshot_digest, level_index)` 状态键、显式 `win_state` 和 `support_reason()`；状态无法建立时 fail-closed。

- 这些改动改善的是离线 EngineBackend 的安全性和诊断性；没有改变 remote wrapper 无 `_game`、线上不能 snapshot/restore 的事实。
- 本次没有新增 `r3-search` 命中、Scorecard、recording 或真实 `WIN` 证据；因此 §0 的结论仍然成立：R3 通用搜索没有提分证据，不能算破零能力。

与《最小可运行闭环》的对账：本 commit 对应“实现增强 + 证据链增强”，不对应“线上 R3 已接入”。后续仍应优先把线上默认后端迁到 learned `(state, action) -> state` 图，并用 recording/replay/verification report 验收。
