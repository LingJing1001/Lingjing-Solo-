# 概念与理论评估（2026-10-10）

> 评估对象：Lingjing-Solo 架构、SmartRouter 打榜路线、世界模型、AOP 小模型、提分策略  
> 分支：`feature/dpl-v14.2-unknown-bench-400`  
> 结论：**竞赛策略与总体方向正确；理论描述略超前于当前实现，需区分「已实现」与「目标架构」。**

| 层面 | 是否正确 | 说明 |
|------|----------|------|
| ARC 打榜主线（plan + 路由 + CEAX） | ✅ 正确 | 与竞赛「步数敏感、隐藏关、可复现 WIN」高度匹配 |
| Lingjing-Solo 五层架构 | ✅ 方向正确 | 单 Agent 世界模型 + 探索/规划/反思，符合 ARC-AGI-3 设定 |

| 「世界模型 + 后验不确定性」 | ⚠️ 部分正确 | 问题诊断对，现有实现尚未达到理论描述完整度 |

## 2. 打榜策略评估

### 2.1 当前核心逻辑

```text
已校准 plan  →  确定性 WIN（主分数来源）
CEAX + hybrid-click  →  unknown 试探
AOP  →  未来辅助，当前不控盘
```

### 2.2 为何正确

ARC Prize 2026 Phase B 的计分方式是 **通关关卡数**，不是「模型有多通用」：

- 隐藏关下，**可验证、可回放的脚本/plan** 比未训完的小模型更可靠
- 本地基线 **7 WIN / 69 关 / scorecard 35.38** 说明路线有效，不是空理论
- 「先补 plan → 再 unknown → AOP 不押主控」与实测瓶颈一致

### 2.3 需注意

- 本地 **200 步** 会低估 INLINE 局（ls20/ar25）；提分验证应统一用 **800 步**（对齐 `MAX_ACTIONS`）
- 本地 25 局 **≠** Kaggle hidden 集分数；Phase B 才是官方基线
- `C:/newtask-pi` 是工程 bug，修掉后 unknown 本地评测才有参考价值

## 3. Lingjing-Solo 架构评估

### 3.1 五层设计（理论）

```text
Layer 0  perception/     ROI 差分、分割、编码
Layer 1  world_model/    Φ 场：转移表、规则置信、循环检测
Layer 2  exploration/    信息增益、规则归纳
Layer 3  planning/       BFS/A* + LLM 顾问（预算节制）
Layer 4  reflection/     循环/冲突/预算触发反思
```

与 ARC-AGI-3「零指令、回合制、步数敏感」设定对齐，**架构方向正确**。

### 3.2 实现与打榜 Agent 的关系

| 组件 | 角色 |
|------|------|
| `lingjing_solo/agent.py` | 五层 Solo Agent（研究/通用框架） |
| `integrations/.../agent/my_agent.py` | SmartRouter v2（**当前实际打榜 Agent**） |

当前冲分主要靠 **路由表 + 预置 plan + CEAX**，不是完整五层在线闭环。

**结论**：架构理论正确，但文档中应明确 **SmartRouter 是打榜主路径，五层 Solo 是长期框架**，避免混为一谈。

## 4. 世界模型（`field.py`）评估

### 4.1 现有实现

`lingjing_solo/world_model/field.py` 核心结构：

| 结构 | 作用 |
|------|------|
| `transition_table` | 记录 `(s, a) → s'` 转移 |
| `predict_graph` | 状态-动作到下一状态的多数票预测 |
| `state_value` | 状态价值启发式 |
| `effect_ema` | 动作效果 EMA 校准 |

`_calibrate_effect()` 把像素变化、推进信号写回 EMA 和规则置信度。

### 4.2 理论诊断（正确）

现有模型是 **点估计经验统计**，缺少：

- 动作效果的 **方差**
- 规则是否可信的 **后验置信度**
- 小样本下的 **不确定性**
- 冲突假设的 **概率权重**

### 4.3 准确定义

工程上应称为 **tabular / heuristic world model**，不是完整概率世界模型：

- ✅ 对确定性规划、短 horizon 够用
- ❌ 对 unknown 长期探索不够

**结论**：问题定义正确；不要把现有 EMA 等同于「已实现的后验分布」。

## 5. AOP 小模型评估

### 5.1 理论定位（正确）

AOP（Action Outcome Prediction）预测：

```text
(观测, 动作) → action_effective / progressed / action 类别
```

**不是**：

```text
(观测) → 下一步该点什么   ← 这才是策略模型
```

标签三分原则（`visual_changed` / `action_effective` / `progressed`）**非常关键**，避免把「画面动了」误判为「过关了」。

### 5.2 方法论（正确）

| 设计 | 评价 |
|------|------|
| episode-disjoint 切分 | ✅ 防泄漏 |
| recording gate + fail-closed | ✅ 数据可信 |
| shadow + `used_for_control=false` | ✅ 安全接入 |
| 低置信回退确定性 planner | ✅ 符合竞赛约束 |

推荐用途（与理论一致）：

- 离线轨迹分析
- probe_planner 信息增益排序
- CEAX epistemic uncertainty 校准
- 跨 game family 迁移风险评估

### 5.3 实现与理论的差距

| 说法 / 期望 | 当前实际 |
|-------------|----------|
| NIFTy Likelihood / optimize_kl / 后验分布 | 16 维 MLP + 三头交叉熵，**无贝叶斯推断** |
| 「小模型打榜」 | AOP 是 **效果 critic**，不是 **策略 actor** |
| 统一 AOP | 存在两套：`neural/aop.py`（DPL 门禁）与 `aop_model.py`（recording 三头），**尚未统一** |
| 训练数据 | 仅 ~2 episode smoke，**远未达 holdout/canary 门槛** |

**结论**：AOP 作为「不确定性校准层」方向正确；现阶段是 smoke 级监督模型，不能称为完整 epistemic world model。

- SmartRouter v2 多游戏 plan 路由（vc33/sb26/r11l/cd82/tn36/tr87 等 WIN）
- CEAX + hybrid-click unknown 路径
- AOP 数据契约、normalize、train、shadow 流水线（smoke 级）
- Kaggle Phase A 提交流水线（kernel COMPLETE）

## 11. 最终结论

**概念和竞赛策略大体正确**：

- SmartRouter + 校准 plan 是正道
- AOP 辅助定位、shadow 接入方式正确
- 世界模型缺不确定性这一诊断准确
- 提分路线文档可执行

**理论尚未完全落地**：

- 世界模型仍是 EMA 点估计
- AOP 仍是小样本监督 critic
- NIFTy/后验更多是 roadmap，不是现状

**写作与对外表述建议**：凡涉及「世界模型」「后验」「NIFTy」「模型打榜」，应标注是 **目标架构** 还是 **已上线能力**，避免团队内部或对外产生过度预期。
